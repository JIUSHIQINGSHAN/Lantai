# Daily Digest 每日盘点报告

按配置的每日调度点生成记忆盘点报告。默认在 UTC+8 宿主的 23:55 生成当日日报；按需读取入口使用宿主本地的“今日”。

## 报告内容

报告文件默认落**数据根**（`settings.data_home`，票 85）：`LANTAI_HOME` 设了就是
`$LANTAI_HOME/docs/memory-digest/YYYY-MM-DD.md`（Docker 形态即 `/data/docs/memory-digest/`）；
未设 `LANTAI_HOME` 的仓库/开发形态，落点与 db/向量库的推导**同语义**——旧配置
`REMEMBRANCE_HOME` 回填或动态探测命中时随其落用户数据目录，全未配置才回落仓库根
`docs/memory-digest/`。显式 `DIGEST_OUTPUT_DIR` 优先级最高。

| 统计 | 说明 |
|---|---|
| 新增记忆 | 当日创建的记忆数（本地日历日） |
| 修改记忆 | 当日有更新且晚于创建的记忆数 |
| 记忆总量 | 当前全部记忆数 |
| 待审候选 | 锦囊队列总数 + 今日新增；>0 时报告附处理提醒 |
| 今日归档 | 自动 TTL 归档数 + 当日创建即归档数 |
| 今日检索 | 检索次数、零结果数、系统噪音数、平均延迟 |
| 反思提案 | 当日反思产生的提案数（自动应用 / 待审 / 拒绝细分，`digest_worker._aggregate_reflection`） |

## 触发方式

- 定时任务：调度器使用 UTC；`DIGEST_CRON_HOUR` 默认 15，分钟位为 55，即每天 UTC 15:55。可改 `DIGEST_CRON_HOUR`，或设 `DIGEST_ENABLED=False` 关闭。
- 按需读取：Hermes 用 MCP 工具 `get_digest`；REST `GET /digest/today`（需 API key，今日文件不存在则生成；文件已存在时正文读取缓存，统计字段实时计算）。

## 时区与完整性边界

库存时间按 UTC 保存；日报、起居注和每日用量按**服务进程的宿主本地日**划分。日窗由 `core.time.local_day_window_utc` 统一把本地 `[D 00:00, D+1 00:00)` 转为 UTC 查询范围。容器以容器内进程看到的系统时区为准，浏览器或用户个人时区不会自动改变报表日期。本票不新增部署时区旋钮。

cron 小时按 UTC 配置，不随报表时区自动换算。既有默认 UTC 15:55 只在 UTC+8 对应本地 23:55；UTC 宿主同一调度点距本地日末还有 8 小时 5 分钟。其他时区部署须将希望的本地触发时刻换算成 `DIGEST_CRON_HOUR`（例如 UTC 宿主要在本地 23:55 触发时设为 23）。固定 UTC cron 不会自动随夏令时切换，本地日窗当前按运行时宿主偏移换算；跨夏令时日期的历史日界尚无完整支持保证。

日末前生成的是截至触发时刻的当日快照，触发后到日末的新数据不保证被这次定时报告覆盖，次日报告也不会把前一日尾部改记成次日数据。即使默认 UTC+8 部署，仍有 23:55–24:00 的尾部；当前实现不承诺自动生成完整的上一日报告。跨午夜后的“今日”指新的一天，不能把前一日文件当作今日报告；已有文件的按需读取也不会自动刷新正文。需要完整上一日口径或跨时区自动对齐时，应另立行为契约，不能仅调整展示文案。

## 与待审队列的关系

报告中的待审数字来自锦囊队列（pending_review）。处理入口：`GET /candidates/pending` + `POST /candidates/{id}/review`，或对 Hermes 说「查看待审候选」；7 天未处理自动归档为 rejected。
