# LongMemEval 留证修订记录（v0.25 窗口票 01，2026-10-27）

## 修订原因

覆盖率 `coverage_full_rate` 0.76/0.80/0.80（vector-only/bm25-only/hybrid-default，基线
2026-10-26 轮，`summary.json`）经逐题映射保真度审计（`coverage_gap_audit.json`）证实
**不是语料缺口，而是评测 harness 两处仪器问题**：

1. **覆盖率判据误用**：`scripts/lme_run.py` 修前 `cmd_query` 把**检索 top-5 映射回的
   会话**传给 `coverage_audit(q, sids)`（`lantai/eval/longmemeval.py:157` 形参语义是
   「已灌库会话清单」），导致：
   - gate 判「无需记忆」的 3 题（1b9b7252 / caf03d32 / 35a27287）检索面为空 → 整题记缺；
   - 88432d0a / 9a707b82（及 vector-only 轮的 c14c00dd）金标在场但没进 top-5 → 记缺。
   审计对 25 个题级评测库只读直查（sqlite `mode=ro`，tags+content 前缀双判据）：
   **25 题金标 session 全部在场，0 真缺**。
2. **灌库丢行**（真缺口，3 行）：session 原文含 U+2028（LINE SEPARATOR）时，
   `json.dumps(ensure_ascii=False)` 不转义它，服务端 `parse_import_lines`
   （`lantai/services/import_service.py`）的 `str.splitlines()` 把 U+2028 当行界，
   一条合法 JSONL 被拆成两段废段 → 25e5aa4f / fea54f57 / 0ddfec37_abs 各丢 1 行
   （各题的 checkpoint 记 `invalid_n=2/10/3`——每处 U+2028 拆出两段废段，其中部分
   段恰好可解析）。**3 行均非金标 session**，故对 recall 无影响、对金标 coverage
   也无影响，但「每 haystack session 恰 1 条可检索条目」的仪器口径被破坏。

## 修复内容（只动评测 harness，不动生产检索语义）

- `scripts/lme_run.py::_ingest_one`：payload 序列化改 `ensure_ascii=True`
  （U+2028 被转义为字面 `\u2028`，行界唯一 = `\n`）。
- `scripts/lme_run.py::cmd_query`：`coverage_full` 改判金标 session 的 **store
  在场性**（幂等重导探针：同 payload 经 `/import/jsonl` 重导一次，每行恰记
  1 duplicate ⇔ 在库；`imported>0` 或 `invalid>0` 如实记缺）。API 单通道，
  无直连库写入；结果带 `coverage_reimport` 证据字段。
- `scripts/lme_run.py`：`query`/`report` 增 `--suffix`（修订轮落独立文件，
  旧轮留证原样保留）。
- 测试：`tests/test_lme_ingest_fix.py` 3 例（U+2028 防拆 + 重导探针 + 半题检测
  不受影响），定向通过（16 passed，含既有 `test_import_jsonl.py` /
  `test_longmemeval_core.py` 回归）。
