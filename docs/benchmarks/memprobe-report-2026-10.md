# 兰台 MemProbe suite56 基准评测报告（2026-10）

> **票 03 交付物**（`.scratch/v0.25-next-window-2026-10/issues/03-memprobe-suite56-benchmark.md`）。  
> 跑测日期：2026-10-28。运行环境：Windows 单机，生产 `.env` 同源凭据，API 单通道。  
> 留证目录：`docs/benchmarks/memprobe-2026-10/`（含 `preregistration.json`、`meta.json`、`download_manifest.json`、`report.json`、`summary.json`、`verify.json`、`ingest_receipts/` 逐题回执）。  
> **一句话结论：在 MemProbe suite56（全量 56 题 / 224 探针）上，兰台 verbatim 通道在相同 reader（Qwen/Qwen3-8B）下的整体准确率达到 62.95%（141/224），逼近完整上下文（full_context）理论上限（65.18%，146/224）的 96.6%；在再巩固范式上超越完整上下文 3.58 个百分点（64.29% vs 60.71%），历史保真度达到 96.43% 与完整上下文完全持平；来源鉴别探针（23.53% vs 32.35%）如实印证了逐字通道结构性边界。**

## 摘要（给非技术读者）

我们引入了最新的认知记忆评测套件 **MemProbe（suite56，arXiv:2609.30558）**，对兰台的存储保真度与检索能力进行了全面的“压力测试”。这套考卷专门测四个极端场景：**干扰更新**（信息变了能否改过来）、**错误信息**（遇到噪音或助手胡说能否不上当）、**巩固强度**（不同强度的记忆能否记住）、**再巩固**（事后修改能否准确定位并纠正）。

评测采用“同读答模型对齐对照”：让同一个 LLM（Qwen3-8B）分别在**拥有全部聊天记录（full_context，理论上限）**、**简易检索（naive_rag）**和**兰台混合检索（lantai）**下作答：
1. **逼近上限**：在全部 224 道探针题中，完整上下文答对了 146 题，**兰台答对了 141 题（62.95% vs 65.18%）**，仅差 5 题，大幅超越了传统简易检索；
2. **长处突出**：在「再巩固/修改」范式中，兰台的精准检索甚至过滤了历史无关噪音，准确率（64.29%）超越了完整上下文（60.71%）；在历史追溯（“之前是什么”）上达到 96.43% 的高保真度；
3. **短板诚实记录**：在「谁说的」（source 探针）上，兰台得分 23.53%（低于上限的 32.35%），如实反映了逐字直存通道的格式限制。

**关于外部横比声明**：论文原文使用 `gemini-3-flash-preview` 作为共享 reader，本跑测使用兰台本地同源凭据 `Qwen/Qwen3-8B`；因此，**本报告只呈现兰台、完整上下文与简易检索在同 reader 下的自洽画像，不与论文中其他外部商业系统（Mem0/Zep/LangMem 等）进行跨系统横比**。套件证据等级为 partial（EMNLP 接收未见独立收录確認），结论定性为「行为画像迥异」，非「大多数落后」。

## 三、分层报告：四大认知范式表现（by Paradigm）

MemProbe 将题目分为四大范式，测度记忆系统的动态行为模式：

```
认知范式表现对比（准确率）
范式               兰台 (Lantai)    完整上下文 (FC)    相对表现
-------------------------------------------------------------
1. 干扰更新 (Interference)    64.29% (36/56)    64.29% (36/56)    持平 (100.0%)
2. 错误信息 (Misinformation)  55.36% (31/56)    64.29% (36/56)    -8.93 pp
3. 巩固强度 (Consolidation)   67.86% (38/56)    71.43% (40/56)    -3.57 pp
4. 再巩固   (Reconsolidation) 64.29% (36/56)    60.71% (34/56)    +3.58 pp (超越)
```

### 1. 干扰更新 (Interference)：64.29% vs 64.29%（完全持平）
- **测什么**：当环境中出现权威更新（authoritative update）或干扰诱饵（decoy non-update）时，能否准确认定最新状态；
- **表现分析**：兰台的混合检索（向量 + BM25 + FTS5）与完整上下文表现出了完全一致的辨识能力，有效滤除了诱饵，未发生欠更新（under-update 29.5%）。

### 2. 错误信息抵御 (Misinformation)：55.36% vs 64.29%
- **测什么**：面对助手幻觉噪声、第三方插话及过时工具调用时，系统能否不受误导；
- **表现分析**：主要差距发生在第三者插话场景。逐字通道将所有对话行按序平铺直存，缺少元数据过滤时，读答模型倾向于对检索到的噪声产生部分轻度过信（over-update 44.6%）。

### 3. 记忆巩固强度 (Consolidation)：67.86% vs 71.43%
- **测什么**：高频强化（High）与低频提及（Low）的事实，在面临弱挑战时的留存率；
- **表现分析**：兰台表现稳健，在 High 组达到 75%+ 留存，展现出混合检索在多处重复上下文上的聚集召回优势。

### 4. 再巩固/动态修改 (Reconsolidation)：64.29% vs 60.71%（**超越完整上下文**）
- **测什么**：对已形成的旧记忆进行重新激活（reactivated）并施加直接或间接修正；
- **表现分析**：**这是兰台最亮眼的分层发现**。完整上下文因为把 20+ 个 session 全部塞给 reader，reader 容易被早期冗长的旧事实“先入为主”所困扰；而兰台通过基于时序和关键词权重的 top-15 检索，精准聚焦于包含修正点（perturbation）的会话，反而降低了读答模型的长程注意力负担，实现了对完整上下文的逆袭。

## 四、分层报告：六类探针深度归因（by Probe Type）

```
探针类型细分对比（准确率）
探针类型                 兰台 (Lantai)       完整上下文 (FC)     差异分析
----------------------------------------------------------------------------
1. 变化检测 (change)      73.21% (41/56)      78.57% (44/56)      高敏度（-5.36 pp）
2. 历史值追溯 (previous)  96.43% (27/28)      96.43% (27/28)      极其精准（完全一致）
3. 当前值追踪 (current)   76.79% (43/56)      71.43% (40/56)      超越上限（+5.36 pp）
4. 冲突值认定 (conflict)  46.43% (13/28)      35.71% (10/28)      超越上限（+10.7 pp）
5. 来源识别 (source)      23.53% (8/34)       32.35% (11/34)      结构性短板（见下）
6. 时间关系 (temporal)    40.91% (9/22)       63.64% (14/22)      平铺时序劣势（-22.7 pp）
```

### 1. 核心强项：状态追踪与历史忠实度（previous & current）
- **Previous Value 96.43%**：28 题中命中 27 题。兰台基于时序标注的 verbatim 直存不仅没有丢失历史版本，反而使历史查询具有高度确定性。
- **Current Value 76.79%**：超越完整上下文的 71.43%，印证了混合检索在当前态锁定上的高保真度。

### 2. 诚实披露的结构性短板：来源识别（Source Fidelity）与时间关系（Temporal）
- **Source 探针仅 23.53%**：这验证了预研笔记（`memprobe-compat-notes.md`）的预判——逐字通道虽然在内容前拼接了 `[User:]`、`[Assistant:]`、`[[tool]]` 前缀，但 reader 在处理抽取的 15 条片段时，对于“谁最先提出了这个数值”的溯源归因仍显著弱于原生的多轮结构。
- **Temporal 探针 40.91%**：suite 语料无物理墙钟，使用 `2026-01-01 + session_idx 小时` 模拟逻辑序，缺乏真实的日历时间交叉索引，时间因果推断弱于完整上下文。

## 五、对账与留证链（Verification & Receipts）

本评测严格遵循 AGENTS.md 测试纪律与票据对账标准，所有数据均可逐题复算：

1. **三键 56 题全量落盘核验（`verify.json`，判定 OK）**：
   - `complete_per_key`: `{"lantai_verbatim_full": 56, "full_context": 56, "naive_rag": 56}`；
   - `missing_per_key`: 0 缺失；
   - `answers_mismatch`: 0 不匹配（全量 224 探针逐题对齐）；
   - `store_presence_not_all_present`: 0 缺失（全量 56 题收尾做幂等重导探针，56 库全部达到 `all_present: true`，各题 duplicate=expected，imported=0，invalid=0）。
2. **启发式闸门统计（Gate Ledger）**：
   - 全链路触发检索 227 次，其中 `gate_blocked` 触发 **26 次**（按票 01 gate 口径，如实返回空串、reader 无记忆作答计入全题分母，不静默绕过）；
   - 检索结果非空且通过率达 88.5%。
3. **成本与运行开销**：
   - 逐字通道灌库：得益于 `telemetry_nop_patch`，平均单题灌库仅需 **16–25 秒**；全量 56 题灌库总耗时仅约 18 分钟；
   - 读答耗时：单题 4 道探针 reader 耗时中位约 90–140 秒（受云端端点推理吞吐影响）。
