## P0：注入帧叫模型调用一个默认档里不存在的工具

**在哪**

- `scripts/shell_hook.py:63`：`_OFFLOAD_SUFFIX = "…（已卸载全文；可调用 offload_read 工具查看）"`。超过 `SHELL_HOOK_OFFLOAD_CHARS` 的记忆注入时只放摘要，后面接这句话和全文路径。
- `scripts/shell_hook.py:67`：截断指南 `_RECALL_TOOLS_GUIDE_TRUNCATED` 同样写「已卸载全文可调用 offload_read 查看」。
- `lantai/cli/mcp.py` 的 `HERMES_CORE_TOOLS`：`ff1dd12d` 起它是默认档的全部暴露面，只有 `search / add / feedback / core_memory_get / mem_recent`。
- `docs/hermes-install-handoff.md` 第 66–74 行的 Hermes `mcp_servers` 配置没有设 `LANTAI_MCP_PROFILE`，也就是按文档装的 Hermes 走的正是默认档。

**复现（在 `dbde7dd2` 上实测）**

不设 `LANTAI_MCP_PROFILE` / `MCP_TOOL_PROFILE`，起 `python -m lantai.cli.mcp`，依次发 `initialize`、`tools/list`、`tools/call offload_read`：

```
tools/list: 5 ['add', 'core_memory_get', 'feedback', 'mem_recent', 'search']
offload_read call: {"code": -32602, "message": "unknown tool: offload_read"}
```

**为什么全量测试没抓到**

`ff1dd12d` 给依赖非核心工具的 34 个测试模块打了 `pytestmark = pytest.mark.mcp_full_surface()`，其中包括 `tests/test_offload.py`。这些测试拿全量面跑 offload_read，当然是绿的；但用户的 Hermes 拿的是默认档。没有任何测试把「注入帧点名的工具」和「默认档暴露的工具」放在一起比。

**影响**

超长记忆在 Hermes 里只剩摘要，模型按提示去取全文会失败。全文文件还在磁盘上，模型在 Hermes 里能不能直接读文件取决于宿主配置，但兰台自己给的那条路断了。

**修法（本 PR）**

把 `offload_read` 加进 `HERMES_CORE_TOOLS`。理由：

- 它只读，不写任何表；
- 归属校验在 `lantai/services/offload_service.py`：按 memory_id 反查归属，`principal=None` 也收敛校验（票 10），文件名白名单加防穿越；
- 它是注入链路本身的一环（注入帧主动叫模型用它），不属于「运维/全量面」。

其余 90 个工具的收窄不变，`LANTAI_MCP_PROFILE=full` 的语义不变，`_get_active_tools()` 的 fail-closed 逻辑不变。`LANTAI_MCP_PROFILE=hermes` 同样拿到这 6 个，和注入帧口径一致。

另一种修法是反过来改 shell_hook，把「可调用 offload_read」换成「读这个路径」。没选它，因为那样等于让模型直接读本地文件，绕开 offload_service 的归属校验。

**回归锁：`tests/test_hook_named_tools_in_default_profile.py`（3 个测试，不打 `mcp_full_surface`）**

1. 合同：扫描 `scripts/shell_hook.py` 里所有含「调用」或「工具」的模块级字符串常量，取出其中点名的已注册 MCP 工具，必须全部在默认档 `_get_active_tools()` 里。带非空转检查：必须扫到 offload_read，否则判扫描失效。
2. 端到端：用真实 `build_context` 产出一条卸载注入，从注入文本里取出它点名的工具和全文路径，默认档 `tools/list` 必须包含这些工具；再按路径反推 memory_id，用默认档 `tools/call offload_read`（不传 user_id，和 Hermes 实际一致）拿回完整原文。
3. 归属不松：默认档下不传身份去读 user-B 的卸载全文，仍然被拒，响应里不出现原文。
