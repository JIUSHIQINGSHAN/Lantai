## 一句话结论

兰台在检索侧叠了 decay、lane_boost、rerank、MMR、echo 抑制、errsig、episode credit、supersedes 降位等一长串机制，却没有一条"全部关掉"的极简地板线，无法回答"这些机制各自值不值"。NeurIPS 2026 的一篇论文用一个极简 RAG 记忆就追平了多个复杂记忆系统。建议先把地板线补上。

## P0 返璞——给检索评测加"极简地板线"，逐项消融每个增强机制的净贡献（S～M）

承接：#83 损益簿（评"有记忆 vs 无记忆"）；本条评"兰台全套 vs 极简检索"，两者互补，可共用同一 paired 报告。

### 动机（现状缺口）
- `lantai/retrieval/hybrid.py:25` 的 `RetrievalParams` 已有十余个可开关的增强项（`reranker_enabled`、`mmr_enabled`、`echo_suppress_enabled`、`errsig_bonus`、`episode_credit_enabled`、`supersedes_enabled`、`lane_boost`、`w_decay`）。
- `scripts/run_param_matrix.py:40` 的 `MATRIX` 只在 vector/bm25/fts/decay 四个权重之间挪动（base、vec+、vec++、bm25+、decay+、fts+），**没有"全关"的一行，也没有逐项关闭的行**。该脚本的位置敏感指标只比较各组之间的一致率，不是比较对答案的好坏。
- ADR-0056（episode credit）自己写明"水源解决前不做消融/调权"。现在评测集已有 LongMemEval（`lantai/eval/longmemeval.py`）、E2 时序（`e2_temporal_cases.py`）、遗忘质量（`forgetting_quality.py`），具备做消融的条件。
- 结果是：每个机制的存在理由只靠设计直觉，没有"关掉它会掉多少"的数字。

### 外部依据
- Liu 等，*RAG in a Trenchcoat: When Minimal Memory Is Enough for Agentic Systems, and When It Isn't*，arXiv:2611.22179，2026-11-17 提交，NeurIPS 2026 主会：极简的 BRIDGE（分块观察笔记 + BM25/余弦混合检索 + 按时间顺序渲染）在 LongMemEval-S 与 BEAM 上与此前 SOTA 在 bootstrap 置信区间内持平，并在 EverMemBench 上以相同 reader 高出最强记忆基线 5.7–6.3 分；结论是"抽取、取代、反思、图合成这些原语几乎都不值回成本"，且标准基准只量"检索到什么"，量不到"记忆让 Agent 做成了什么"。
- 同文给出的反面：原子事实抽取在"规则应用"上赢，块摘要在"模式归纳"上赢，没有通吃的架构。所以消融要分题型报告，不能只给总分。
- 已打开页面：https://arxiv.org/abs/2611.22179

（注意：该文用的是英文基准，不能直接推出兰台中文场景的结论；本条的目的正是用兰台自己的评测集把这个问题量出来。）

### 设计要点
1. 在 `scripts/run_param_matrix.py` 增加"消融矩阵"模式（新增 `ABLATIONS` 列表，不改现有 `MATRIX`）：
   - `plain`：vector 0.7 + bm25 0.3、`w_decay=0`、`w_fts=0`、关 rerank/MMR/echo/errsig/episode_credit/supersedes 降位/lane_boost。
   - `plain+X`：在 plain 上每次只打开一个机制（decay、lane_boost、rerank、mmr、echo、errsig、credit、supersedes），共约 8 行。
   - `full-X`：在默认配置上每次只关一个，作为交叉校验。
2. `run_dry_run` 现在的 `param_overrides` 会被统一 `float()` 转换（`lantai/eval/runner.py:65`），布尔开关会变成 0.0/1.0。需确认 `hybrid_search` 对布尔项读取 override 的行为；若不识别，则在 `RetrievalParams` 构造处增加对布尔 override 的显式支持，并加测试。
3. 指标用既有的 LongMemEval session recall@k 与 E2 的 Contamination@k（2026-11-18 的"辨新"），按题型分列，附 bootstrap 置信区间；不引入新依赖。
4. 报告落到 `docs/param-matrix-report.md` 的新一节（沿用现有落盘习惯），列出"每个机制的净增益 ± 区间"。判定规则预先写死：区间包含 0 的机制标为"待证"，不自动删，由人决定。

### 验收与测试
- `--ablation` 能跑出 plain、plain+X、full-X 三组共约 17 行，且每行的 override 在日志里可见。
- 单测：`plain` 配置下 `hybrid_search` 确实不调用 reranker、不做 MMR（用现有评测夹具的确定性嵌入 `deterministic_embed.py`）。
- 报告里每个机制有净增益点估计与区间；样本数不足时直接写"不足以判定"，不给结论。

### 风险与工作量：S～M
- 风险：布尔 override 目前可能被静默当成浮点，导致"关了其实没关"。这是该工作最先要验证的点。
- 风险：评测集偏小时区间会很宽，结论可能是"都判不出来"，这本身也是有用结果。
- 注意：本条只出数字，不据此删除机制。

## P1 规则应用探针——评"记忆让 Agent 做成了什么"，而不只是"检到了什么"（M，仅方向，等 P0 数字）

- 依据同上篇 arXiv:2611.22179 的五类对抗探针（规则应用 ±、模式归纳、多轮动态），关键点是"问题从不提及规则本身，只有应用了记忆里的规则才答得对"。
- 兰台已有"法门"程序性技能与"错题签名"（errsig），恰好是这类探针的对象。可先做 10～20 条中文手写场景，如"记忆里有：发票一律开公司抬头；提问：帮我给客户订一份会议室并开票"，看注入后模型是否应用了规则。
- 先不立项：需要 #83 的回答层评测先落地，才有可复用的出题/判分底座。
