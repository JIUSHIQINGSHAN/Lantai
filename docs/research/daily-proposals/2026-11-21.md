## P0 湮没——删除一条记忆时，沿 source_ids 找出并处置含其内容的衍生记忆（M）

### 动机（现状缺口）
- `lantai/evolution/promoter.py:948` `delete_memory` 的级联：事实原子（`purge_facts_for_memory`，record_ops_service.py:848）、`MemoryEdge`、FTS、向量库——**没有处理“以该记忆为 source_ids 之一的聚合主记忆”**。
- 折叠时（`lantai/services/consolidation_service.py:374-450`）主记忆的 `source_ids` 记下全部碎片 id，碎片标 `consolidated`；主记忆正文是对碎片的概括，里面可能带着被删碎片的内容。用户删掉碎片后，主记忆仍 active 且仍会被召回/注入。反思、进化产物（`cognition/reflection.py:121`、`cognition/evolution.py:292` 等也写 `source_ids`）同理。
- ADR-0005 “永不物理删除”与 `delete_memory` 的物理删除并存，说明“用户明确要求删除”是另一条语义；该语义目前只覆盖一跳（事实、边），不覆盖衍生记忆。
- 以上是**静态阅读结论，本期未实测**；第 1 步先用内存 SQLite 夹具复现（造 3 碎片→折叠出主记忆→删 1 碎片→看主记忆是否仍 active 且含原文）。

### 外部依据
- *Forget the Lineage*（LinEra），arXiv:2611.18133，2026-11-13（已打开摘要）：删一条消息不够，其摘要、抽取事实、嵌入、备份都会残留；在 LoCoMo 上，逻辑删除后攻击者读存储仍恢复 71 条被遗忘秘密中的 70 条；遗忘半径随写入器 fan-in 增大——遗忘 1% 的轮次，会话级摘要波及 73.0% 的衍生记忆，四轮窗口只波及 3.8%。含义：**折叠粒度越粗，删除越要连坐**，且“重新推导”可恢复被连坐的部分。
- LEDGER，arXiv:2611.20927，2026-11-16（已打开摘要）：事实带来源与有效期，由规则决定删什么；删除时同步清洗原始轮次；删除请求只描述事实时，被删值在所有评测探针中都没进入证据。
- 本篇**不建议**上密码学擦除（单用户 SQLite，过重）；只取其“沿血统找衍生物”的思想。

### 设计要点
1. 新增 `find_derivatives(memory_id)`：在 MemoryItem 中查 `source_ids` 含该 id 的行（SQLite JSON 查询或应用层扫描，先量规模），递归到闭包（上限深度可配，ADR-0002 零硬编码）。
2. 删除前返回**影响预览**：`{"derivatives": [...]}`，默认 `dry_run`；`delete_memory` 保持返回 dict 形状只增键（沿用票 36 口径）。
3. 处置策略三选一，设置项控制，默认最保守：`flag`（衍生记忆标“待复核”，不再注入，走知命/待审流程）｜`cascade`（一并删除）｜`rederive`（删除衍生物，保留其余碎片重新进入折叠候选）。默认 `flag`，因为主记忆往往还含其他未删碎片的信息。
4. 被删碎片若已 `consolidated`，其兄弟碎片应可恢复 active（接起复 ADR-0052 的路径），否则折叠后删一条会让整组消失。
5. 审计：留一条无正文的删除回执（id、时间、受影响 id 列表），与 ADR-0084 否决回执终态的风格一致。

### 涉及文件与范围
`lantai/evolution/promoter.py`（delete_memory 增加衍生物步骤）、`lantai/services/record_ops_service.py`（find_derivatives，与 purge_facts_for_memory 同事务）、`lantai/services/source_service.py:140`（delete_document 级联目标也要走同一路径）、`lantai/api/routes_terminal.py:340`、MCP 删除入口、`lantai/core/settings.py`（策略与深度项）。需新 ADR（编号 0091 之后，按 ADR-0013 先登记名字；建议名“湮没”，先查未占用）。无 schema 变更则为 M 下限；若加回执表则 schema v47。

### 验收与测试
- 测试：折叠后删碎片 → 主记忆不再被召回/注入（flag）；cascade 下主记忆与其边、事实、向量一并消失；rederive 下兄弟碎片回到 active。
- 回归：无衍生物时行为与现状完全一致；失败整体回滚（沿用完璧 X-01 同事务范式）；跨用户/租户不会连坐他人记忆（ensure_can_delete 同样检查衍生物归属）。
- 评测：在 eval 加“删除泄漏率”——删除后用探针问被删事实，统计答复中被删值出现比例，目标 0。

### 风险与工作量
M。风险：连坐过度（删一条误伤聚合主记忆）→ 默认只标记；`source_ids` 是 JSON 列，规模大时需索引或预建反向表（先量）；DSH 桥与远程 MCP 需同步更新入参。
