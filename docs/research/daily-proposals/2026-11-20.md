## P0 量水——主动注入的置信度门槛随库规模自适应（M）

### 动机（现状缺口）
- 主动注入走 `scripts/shell_hook.py:303` 的 `build_context`：混合检索后用**全局固定阈值**过滤——reranker 通道 `SHELL_HOOK_SCORE_THRESHOLD=0.5`，RRF 降级通道 `SHELL_HOOK_SCORE_THRESHOLD_RRF=0.15`（`lantai/core/settings.py:295-296`，`tests/test_settings_defaults_frozen.py:301-302` 冻结）。阈值是在小库上定的，没有任何随库规模变化的机制。
- 这是一个“多重检验”问题：每轮对话要在 N 条记忆里取最高分，N 越大，最高的“无关”分数越容易超过固定阈值。库只会越用越大（生产库目前约 930 向量，见 `docs/chroma-migration.md`），误注入率只会单调上升；误注入既占 1500 字符预算（`SHELL_HOOK_MAX_TOTAL_CHARS`），又会把无关记忆当“事实”喂给模型。
- 与 Maya 11-19 巡检 P1-1（生产库 L2 vs 余弦）互相放大：距离口径不一致会让同一阈值在生产库与测试库上含义不同，自适应门槛必须建立在口径统一之后（见“前置”）。
- 现有评测（E2、辨新 11-18）按固定小库测，看不到该效应。

### 外部依据
- *The Price of Scale in Proactive Memory Recall*，arXiv:2610.34507（v3，2026-11-03，已打开）：LongMemEval 回放中，N=8 时调到 5% 误报的相似度阈值，N=2048 时误报升到 84–100%；理论上最优分的单项误报率约 −ln(1−α)/N；交叉编码器同样受影响；提出“cue-swap 共形门”——把当前查询的分数放到“用户其他历史查询在同一库上的分数”里排名，有有限样本误报保证；在 N=2048 的时序回放里误报 5–8%，对比部署门槛 57%，单次决策约 0.4s CPU。代码：github.com/RiverChenStillCompiling/price-of-scale。
- 旁证：*Route to Remember*，arXiv:2611.05636（2026-11-03，仅见搜索摘要）报告 top-1 相似度在对错答案间几乎无区分（0.735 vs 0.741），说明单靠绝对相似度门槛信号弱。**未打开全文，仅作旁证。**

### 设计要点
1. 先做尺子（S，不改行为）：新增离线脚本，用本库真实记忆回放“用户历史查询 + 无答案查询”，在子采样 N=64/256/1024/全量下测当前阈值的误注入率曲线；结果写进 `docs/research/`。若曲线平坦，则本建议降级为只加监控。
2. 经验分位门（M）：为每个用户维护“背景查询集”（最近 K 条用户自己的查询，K≈200，只存查询向量，不存正文），对当前查询的 top1 分数，计算它在“背景查询对同一库的 top1 分数”中的分位；仅当分位 ≥ 1−α（默认 α=0.05）**且**仍满足原绝对阈值时才注入（只收紧，不放宽，保证向后兼容）。
3. 特性开关 `SHELL_HOOK_ADAPTIVE_GATE`（默认关，灰度后再开）；决策与分位写入已有的检索 trace，便于解释“为什么没注入”。
4. 与拾遗（ADR-0069 零召回补救）的关系：门收紧后零召回会变多，拾遗预算 `SHIYI_SCAN_BUDGET_MS` 需联测。
5. 与“弃答”口径衔接：Maya #52 的 LongMemEval `_abs` 口径可直接当验收集。

### 涉及文件与范围
- `scripts/shell_hook.py`（过滤处约 L350-360）、`lantai/core/settings.py`（新开关/α/K）、新增 `lantai/retrieval/adaptive_gate.py`（分位计算，纯函数）、`scripts/` 下新增尺子脚本、`tests/test_adaptive_gate.py`；`tests/test_settings_defaults_frozen.py` 需登记新默认值。
- 新增 ADR（编号按 ADR-0013 先登记；当前最新 ADR-0090）。不需要 schema 迁移（背景查询向量先放内存/临时文件；若要持久化再另开票）。

### 验收与测试
- 单测：构造 N 递增的合成库（无关记忆为随机单位向量），固定阈值下误注入率随 N 上升，自适应门下稳定在 α 附近。
- 回归：`tests/test_score_threshold_dimension.py` 全部通过；开关关闭时行为与现在逐字节一致。
- 召回不下降：在已有评测上，开启后命中率下降不超过 2 个百分点（以尺子脚本实测为准，这是建议值，不是论文结论）。
- Hook 2 秒预算（`SHELL_HOOK_TIMEOUT`）内完成：分位计算只用预存向量，不再调用 embedding。

### 风险与工作量
- M。风险：冷启动期背景集太小（<30 条时回落固定阈值）；用户查询分布突变；背景集含隐私，只存向量并随会话清理策略（承接 Maya 11-07 `on_session_delete`）。
- 前置：Maya 11-19 P1-1 的距离口径决策（改余弦或换算）；未决前尺子脚本应分别在 l2/cosine 库上各跑一遍。

## P1 对错并检——StaleBench/DISCERN 口径补进评测（S，承接 11-18「辨新」）

- StaleBench，arXiv:2611.19752（2026-11-15，已打开摘要）：892 条真实更新事实，Contamination@5 能在 current@1/current@5 排错的地方给出正确排序；撤掉词面锚点会让现有键控机制损失数十点新鲜度。与 11-18 已提的 Contamination@k、同义锚点鲁棒性**重合**，所以这里只建议：把其“currency 标签来自来源（Wikidata 有效期）而非检索分”的做法作为 E2 标注规范，不另开新工作。
- DISCERN，arXiv:2611.15729（2026-11-11，已打开摘要）：召回/保持/时效在合成企业库上已近饱和（0.93–0.98），剩下的难点是实体消歧、当前时间态、该不该作答（弃答）。对兰台的含义：评测重点应从“找得到”转向“该不该答”，与 P0 的门槛、Maya #52 的 `_abs` 口径同向。仅作评测设计参考，不建议现在写代码。
