# Iteration 08 — 论文纵深综合：三大机制集群与兰台映射（2026-09-19）

## 类型
synthesis（基于 R2 已核验的 32 篇论文元信息 + 摘要）

## 集群 A：RL 记忆管理（Mem-α 2509.25911 / Memory-R1 2508.19828 / Fine-Mem 2601.08435 / Mem-π 2605.21463）
- 共同主张：**「存什么/怎么结构化/何时更新」不该靠手写提示词**，可由 RL 从任务回报中学出。
- Fine-Mem 指出核心难点：最终任务奖励太稀疏，单条记忆操作的信用分配需要逐步/细粒度奖励。
- 对兰台：兰台的 gate/考功/反思是**规则+人工审批**路线；RL 路线依赖可自动判分的任务流。开发场景中「任务是否成功」信号弱（人工判定成本高），故 RL 只宜作**影子观察**（记录操作与结果，离线分析），不应进入生产调权——与 2026-09-18 调研「episode 影子记录」结论一致。

## 集群 B：巩固与遗忘（LightMem 2510.18866 ICLR 2026 / Oblivion 2604.00131 / SCM-Sleep 2604.20943 / TRUSTMEM 2606.25161）
- LightMem：Atkinson-Shiffrin 三阶段（感觉/短/长时）+ 两级压缩 + **闲时更新**，主打性能-开销平衡；被 ICLR 2026 接收说明「高效巩固」已是主流研究议题。
- Oblivion：遗忘=**可及性衰减**而非显式删除；读写路径解耦，读路径按 agent 不确定性决定是否查记忆——与兰台 decay_score 归档语义同构。
- TRUSTMEM：写/改/删操作本身可能遗漏/损坏/幻觉，错误一旦入库成为**持久系统状态失败**——为「闸门+检查点+回滚」提供了学理依据。
- 对兰台：沉潜（闲时巩固）与 LightMem 的 sleep-time 更新直接同构；TRUSTMEM 提示巩固产物也要过审（兰台反思提案已如此设计，应写进评测用例）。

## 集群 C：治理化共享记忆（Governed Shared Memory 2606.24535 + Zep 论文 + 樊篱对应物）
- 四大失败模式：**越权泄漏、陈旧传播、矛盾存续、血统崩塌**；对应四原语：scoped retrieval、temporal supersession、provenance tracking、policy-governed propagation。
- 对兰台：四原语兰台各有对应物（辨域 ACL/回声抑制时间窗+知命/provenance/待审策略），**但缺 temporal supersession 的数据基础**（R7 核验：无事件时间字段）——治理叙事成立，时效治理缺口实锤。
- 多智能体共享记忆是 2026 新兴议题；兰台「持节」自主审批是治理面的差异化入口。

## 元观察
1. 论文界与产品界在收敛同一组问题：写入精度、时效、巩固、遗忘、治理——2026-08 报告的「选择性遗忘成为主战场」判断被论文集群进一步佐证。
2. 兰台的机制组合（闸门→待审→提案→检查点→衰减→巩固→考功）在论文中**每一步都有对应研究**，但**端到端成链且带人工闸门的公开系统样本仍稀缺**——这是可外宣的定位缺口。
3. 方法论警示：RL 系论文的效果以自动判分环境为主，开发/中文场景迁移证据为零。

## 决策
- D16：路线图新增观察项「RL 影子学习」（不做实现承诺）；巩固类采纳 LightMem 佐证「沉潜」优先级。
- D17：治理叙事升级为四原语对齐（scoped retrieval / temporal supersession / provenance / policy propagation），把兰台已有机制翻译成社区通用语言。
