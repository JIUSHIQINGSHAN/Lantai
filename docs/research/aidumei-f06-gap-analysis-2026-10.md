### 2.2 失败分级

**上游声明（partial，报告 §三.6；来源 Releases + README f0.4+ 节，2026-10-25）**

- f0.4 前：HTTP 451 内容拒答曾被当成「可能已写入」，导致同记忆域后续写入全被 409 锁死；
- f0.4+ 修复声明：失败发生在任何写入之前；如实记「未写入」；原文走确定性路径照常落库、只跳过语义蒸馏；拒答不计入熔断。

**兰台现状（仓内证据）**

- 「宁 miss 不脏写」总纪律（AGENTS.md）：校验失败不静默丢弃、不自动修正，候选进锦囊 pending_review 交裁决，超龄自动归档 rejected；
- 笔削四分法（ADR-0047）：纠错/撤回/归档/删除语义分离，验收口径「撤回后禁用命中=0」；
- 勘合（v0.23.0「六闸」之一）：任务失败释放幂等键使重试可执行，回执零正文只存标量；
- 沉潜单簇故障隔离（CHANGELOG 0.23.5）：失败簇回滚半成品事务、异常进 warnings 不静默；
- 提取失败如实标注不静默（v0.24 票 01 留证：`ingestion/dialogue.py:205-214` 标 `event_time_extract_failed`，宁 miss 不脏写）。

**悬置项裁决（报告 §六，原样保留）**：上游式失败语义三态分级（拒答/服务故障/不确定写入 + pending_review 配套）**不立项，仅记差距分析备查**——兰台未发生过上游那类「一次拒答锁死写入域」事故（至少无记录）；写入失败路径现状已经 v0.24 票 01 第④路目检（无雷）。

**判定**：上游教训的可取处是「失败必须发生在任何写入之前 + 失败如实记账」两点，兰台既有纪律已覆盖其意图；三态分级留作备查，出现真实同类事故再立票。

### 2.3 预算参数

**上游声明（partial，报告 §三.7；来源 Releases + README，2026-10-25）**

- f0.3+/f0.4 可选决策模型使检索全链路 p50 慢约 68%、p95 慢约 120%（**上游自测口径，其 README 自声明不可当生产数据**）；
- 缓解参数模板：3 次外呼/3000ms 共享预算、60s 缓存、并发上限 2、连续 3 失败熔断 30s；
- f0.3 进程级 LLM 并发闸门（`AIDUMEI_LLM_MAX_CONCURRENCY` 默认 4，f03 文 §3.1 G1）；
- f0.3 另修复 consolidator 假删除记零（日志写「删除 0/N」实际照常删除）与墓碑恢复不重建向量（雷清单对照见 §三）。

**兰台现状（仓内证据）**

- 进程级 LLM 并发闸已移植（v0.23.0「并发闸」）：`lantai/core/settings.py:43` `LLM_MAX_CONCURRENCY: int = 4`，`lantai/llm/client.py:86` 三通道（chat/vision/embed）共用（2026-10-27 grep 实测在位）；
- MCP 工具循环守卫已移植（v0.23.0，f03 文 G2 挂靠票 06：5 次/60s + 冷却 30s）；
- 司天 24h LLM 降级率一级指标（v0.24.0）：`collect_llm_degrade` 三态 no_evidence/ok/degraded、零调用不装绿，≥10 次且失败率 ≥50% 判 `llm_degrade_high`；
- 决策模型可选通道：**不跟**（f03 文 §五：上游自己默认关闭、本地模式直接禁用；强依赖 mem0 事实模型，与兰台四路混合检索不同源）。

**判定**：通用面（并发闸、失败守卫、降级观测）兰台已具备且参数独立标定（默认 4 vs 上游闸默认 4、决策模型通道上限 2，场景不同不作优劣结论）；决策模型预算参数仅作**参数模板备查**——不跟裁决在先，无移植对象。

### 2.4 Windows 边界

**上游声明（verified，报告 §三.8；来源 README 测试与质量节 + f0.5 Release，与 GitHub API 交叉，2026-10-25）**

- consolidator/restore 等运维脚本仍 POSIX-only；全量测试仅 POSIX 保证；
- 策略定性（报告原话）：「降级 + 显式声明边界而非假装跨平台」。

**兰台现状（仓内证据）**

- 维护者开发与日常运行环境即 win32（本仓在本机 Windows 上开发、测试、发版；报告 §三.8 亦注明「维护者环境即 win32」）；
- 兰台对自身运维脚本的 Windows 平台假设**未见专门盘点**（资料缺口，如实标注；本次仅确认 `scripts/check_ingest_wiring.py` 等脚本存在，未做平台面审计）。

**判定**：策略借鉴件，无代码可移植。「降级 + WARNING 留痕 + 显式声明边界」与兰台「宁 miss 不脏写、降级如实声明」纪律同构；平台面盘点列入 §七资料缺口。
