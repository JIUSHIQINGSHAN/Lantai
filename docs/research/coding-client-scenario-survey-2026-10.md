> 核心定义：「编码客户端（Claude Code / OpenCode 类）作为一等公民场景」定义为：若评估通过，编码宿主将作为与通用 API 并列的**官方支持与自动化测试对象**。
> 约束纪律：不预设结论；不依据已被推翻的「头部玩家收敛」泛化假设；仅以两项 partial/unconfirmed 级具体观察为输入，客观评估接入成本与维护面。

## 一、外部竞品与参考观察（带证据等级）

1. **TencentDB-Agent-Memory（partial，来源：releases.atom / v2.0.2 2026-10-09）**：
   - 在 v2.0.2 发布中增加对 OpenCode 与 Pi 客户端的适配，通过独立接入模块提供上下文同步。
   - 证据特征：有公开发布与提交历史，但未公布大规模多开发者日常使用的稳定性与召回改善数据（故定级为 partial 观察）。
2. **Letta Code 形态（partial / unconfirmed，来源：letta-code 仓库与 blog）**：
   - Letta 推出 `letta-code` 专项形态，将 Agent 记忆与编码工作区环境深度集成，保持长程代码重构与指令意图记忆。
   - 证据特征：日更节奏活跃，定位从通用 memory agent 向 coding workflow 聚焦，但其架构多基于专用状态服务，属于单一厂商的产品路线选择，尚未形成跨工具通用标准（定级为 partial/unconfirmed）。
3. **行业归纳收敛性核实**：
   - 经 2026-10 复核，「头部厂商全面收敛至编码客户端记忆」的泛化归纳已被推翻作废；当前仅能采纳的单一事实是：**编码客户端接入是至少两家竞品在做的具体实验性动作**。

## 二、三种接入形态比选表

| 比选维度 | 形态 A：MCP Server（模型上下文协议） | 形态 B：Hook 适配（Shell / Event Hook） | 形态 C：客户端专属插件（IDE / CLI Plugin） |
| :--- | :--- | :--- | :--- |
| **接入成本** | **低（已具备）**：直接复用标准 JSON-RPC 2.0 stdio 协议（兰台现役 `lantai.cli.mcp`），跨 Claude Code、Cursor、OpenCode 通用。 | **中**：需按宿主生命周期（pre-command、post-command、user-prompt-submit）编写轻量调用脚本（如 `shell_hook.py` 或 `lantai_remote_hook.py`）。 | **高**：需针对每个客户端宿主（VS Code 插件体系、JetBrains、Claude Code 扩展等）编写专用包并维护 API 变动。 |
| **维护面与依赖风险** | **极小**：协议标准化，单人维护仅需看护 1 份标准 tools 契约；客户端侧升级只要保持 MCP 规范即可向后兼容。 | **中小**：依赖宿主暴露的环境变量与 hook 点；若宿主 CLI 更新 hook 触发参数，需同步修补。 | **极大**：多宿主生态碎片化严重，单人维护无法承担持续跟进多个 IDE/CLI 插件生命周期的负担。 |
| **功能表达力与控制度** | **高（双向按需）**：模型可在推理循环中自主决定调用 `search`、`add`、`put_core_memory` 或 `rollback`，带参数语义与错误回显。 | **中（单向透明注入）**：主打 prompt 注入与静默回执，模型无法在单轮对话内自主发起二次交互查询。 | **最高（深度定制）**：可定制专有 UI、侧边栏面板、快捷键等。 |
| **自动化测试与可验证性** | **优秀**：已有完整且确定性的 stdio 测试套件（如 `tests/test_mcp.py`），CI 完全自包含、不 mock 冒烟。 | **良好**：可通过 stdin/stdout 构造受控 JSON 冒烟测试（如 `tests/test_shell_hook.py`）。 | **较差**：严重依赖 UI 自动化驱动与多宿主桌面运行环境，单人本地自动化回归极难保证。 |
| **与兰台单人维护匹配度** | **极高（天然契合）**：符合「零额外外部依赖、内嵌轻量、统一标准」架构原则。 | **良好（作为辅助静默通道）**：适合维护者自身日常 dogfooding 注入。 | **不匹配**：违背 YAGNI 与单人维护工时边界。 |

## 三、评估结论与决策建议

### 结论：【暂不】（作为与通用 API 并列的一等公民测试对象），维持【MCP 优先作为官方接入通道】

- **结论状态**：**暂不立项为与通用 API 并列的官方一等公民**。
- **证据等级**：**partial**（基于外部两家竞品动作样本不足、且行业未收敛为统一标准的事实）。
- **具体裁决理由**：
  1. **不立项为「一等公民」**：兰台的定位是单人维护、本地优先、专注生命周期与遗忘治理的记忆基础设施。若将多款编码客户端列为与通用 REST API 同级的官方支持与测试对象，将成倍增加跨操作系统、多客户端版本的回归矩阵负担。
  2. **现状已足够支撑编码场景**：现有的 **形态 A（MCP Server）** 已经是 Claude Code / OpenCode 等现代编码客户端的工业界标准规范，兰台已通过 MCP 暴露记忆工具，无需再为编码客户端单独开设「专用方言接口」或维护专属插件。
  3. **Dogfooding 走轻量 Hook 即可**：针对维护者日常使用 Claude Code 进行开发 dogfooding 的需求，继续沿用现有的 `settings.json` hook / 轻量远程 hook 注入方式，足以提供影子数据水源，无需过度设计。
