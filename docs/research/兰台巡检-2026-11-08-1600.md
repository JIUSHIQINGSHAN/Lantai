## P2：wheel/容器形态下三个文档写面的默认目录逃逸 LANTAI_HOME——digest 每日必炸、/digest/today 恒 500

**在哪**

- `lantai/workers/digest_worker.py:26-27`、`lantai/services/offload_service.py:13-14`、
  `lantai/services/wiki_service.py:26-27`：三个默认输出目录全部按
  `Path(__file__).resolve().parent.parent.parent`（**安装前缀**）推导 → `<prefix>/docs/*`。
- **对照正确范式**：`lantai/core/settings.py:548`
  `home = Path(self.LANTAI_HOME) if self.LANTAI_HOME else _REPO_ROOT`——db/chroma 落
  `LANTAI_HOME`（Docker 里即 `/data`，:33），唯独这三个写面绕开它。
- **发布形态**：`Dockerfile` :14 wheel 构建 → :23 `pip install /wheels/*.whl`（lantai 进
  `/usr/local/lib/python3.11/site-packages`）→ :39 `useradd -u 1001 appuser` + :40
  `USER appuser`——**安装前缀 root 所有、进程非 root**；`VOLUME /data`（:30）只保住数据面。
- **触发必然性**：`DIGEST_ENABLED: bool = True` 默认开（`settings.py:86`）、
  `DIGEST_OUTPUT_DIR` 默认空（:88）；全仓 grep 无任何部署面（.env.example / docs/compose /
  README）设置它；API lifespan `init_db()` + `start_scheduler()`（`lantai/api/app.py:81/:95`）
  → 每日 digest cron 必触发 `write_digest_report` → `_digest_dir().mkdir(parents=True)`
  （`digest_worker.py:564`）在 root 只读前缀下 **PermissionError**。

**复现（`_r10_probe_wheel_write_paths.py`，真 wheel + 临时 LANTAI_HOME，PASS）**

```
lantai loaded from: .../_r10_wheelprobe/sp/lantai/core/settings.py   ← wheel 副本非仓代码
LANTAI_HOME(env) = .../Temp/lantai-probe-home
db url           = sqlite:///.../lantai-probe-home/remembrance.db    ← 数据面正确落 LANTAI_HOME
digest  _DEFAULT : .../sp/docs/memory-digest                          ← 写面无视 LANTAI_HOME
offload _DEFAULT : .../sp/docs/memory-offload
wiki    _DEFAULT : .../sp/docs/memory-wiki
write_digest_report -> .../sp/docs/memory-digest/2026-11-08-probe.md
INSIDE_LANTAI_HOME = False
INSIDE_INSTALL_PREFIX = True                                          ← 报告实际写进安装树
```

本机 Windows 下安装前缀可写所以「写成功进安装树」（本身就是反常）；容器内同一路径 root
只读即 PermissionError。**维护者一行验证**（本机无 docker，此臂未跑，如实声明）：

```
docker run --rm --entrypoint python ghcr.io/JIUSHIQINGSHAN/lantai:vX.Y.Z \
  -c "from lantai.workers.digest_worker import _digest_dir; _digest_dir().mkdir(parents=True, exist_ok=True)"
```

**爆面分级（按 sink）**

| sink | 容器内表现 | 级 |
|---|---|---|
| digest | ①每日 job PermissionError（`record_run("digest")` 在写后永不执行 → 司天 staleness 兜底可见）；②`GET /digest/today`（`lantai/api/routes_digest.py:18-20` 薄路由零兜底）文件永不存在 → 每次现算 → **500**；③MCP `get_digest` → -32603 | P2 |
| offload | `scripts/shell_hook.py:163-176` `_format_offload_entry` `except Exception` **静默降级**为截断注入、零日志——容器内每次长记忆注入全文丢失无痕（fail-soft 语义本身正确，缺可观测） | P3 |
| wiki | `lantai/services/mem_command.py:94-100` `mem:sync` 兜底带 warning 日志（降级可见，功能死） | P3 |

**docs 失真**：`docs/daily-digest.md:7` 只写仓库形态输出位置，wheel 形态下既不真也报错。

**建议动作**：三写面默认目录归一到 `LANTAI_HOME` 推导（settings 补 `data_home` 属性单一
真源，`LANTAI_HOME` 未设时维持 `_REPO_ROOT` 现状——仓库形态零变化）；offload 降级臂补
warning。或拍板「容器必须显式设 `DIGEST_OUTPUT_DIR`」为契约则 docs/deploy 面明文 + digest
fail-soft——二选一，不许两头都不做。验收与涉及文件见票 85。

**探针伪影留痕**：探针首版直调 `collect_digest_stats` 曾撞 `no such column:
memoryitem.injection_count`——那是直调绕过 `init_db`（生产端 app.py:81 启动必跑迁移）的
伪影 + 命中维护者用户级旧数据目录（`~/.remembrance-data`），**不立案**，仅留痕防复跑者误判。

## P3：digest 置信桶「终桶含 1.0」判定挂在 label 字面量上——settings 桶定义一改静默漂移

**在哪**：`lantai/workers/digest_worker.py:139`
`if lo <= conf < hi or (label == "0.9-1.0" and conf == 1.0):`——终桶收 `conf == 1.0` 的判定
挂在标签字符串字面量上，真源是 `settings.DIGEST_CONF_BUCKETS`（`lantai/core/settings.py:524-530`，
终桶 `("0.9-1.0", 0.9, 1.0)`）。今天恰好一致；任何人按 ADR-0002 反硬编码精神调整桶定义后，
`conf == 1.0` 静默落进 :143 的 magic label「其他」——不 crash 不告警，两处渲染
（:409-410 / `render_calibration_markdown`）会把未知标签并排渲染，报表语义错无人知。

**怎么验证它确实是问题**：临时把 settings 终桶标签改成 `"0.9-0.95"`（阈值不动），真内存库
灌一条 `confidence=1.0`、`decided_by="reflect"` 的 MemoryProposal，真调
`_aggregate_reflection` → 该条落「其他」而非终桶。修法与验收见票 86（终桶判定改数值语义、
「其他」标签同源化、回归锁用改名后的桶定义直调断言）。

  `evolve_worker.py:86-90`），不重复立案。

  `RawDocument.content_hash` unique 约束（`lantai/models/tables.py:55`）兜住脏写——
  并发代价是落败方单 job 失败（IntegrityError → 外层 except → job failed），非数据病；
  触发面窄（cron × admin 手动，票 19 已把手动面收 admin），登记不立案。

  git」fail-soft——与 F1 同族但无爆面，仅在票 85 修 `data_home` 时顺带对齐。
