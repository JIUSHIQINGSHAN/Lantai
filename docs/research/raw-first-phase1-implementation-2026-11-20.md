## 本期实现

会话原文由新的显式接口接收。正文与唯一待处理作业在同一 SQLite 事务提交后，才返回保存回执。模块支持独立进程恢复、有界重试、消息身份去重和严格作用域。不同消息 ID 的同文字保留为两次发生，删除清空正文及哈希、撤销作业令牌，并保留零正文身份防止延迟重放。

REST 在读取正文前验证有效凭据，并按实际字节数限制请求。Markdown 下载按权限返回原文，代码围栏防止正文中的 Markdown 被当作外层结构解释。下载不会写入服务器目录或 Obsidian 笔记库。[接口说明](<../conversation-capture.md>) · [架构决策](<../adr/0091-conversation-message-capture.md>)

`FEATURE_CONVERSATION_CAPTURE` 默认关闭。此阶段提供保存与恢复基础，不接宿主自动采集，不调用提取或嵌入模型，不生成生效知识，也没有自动处理 worker。已有写入入口与 MCP 工具面不变。后续阶段需要接入来源关联、提取与人工裁决，再根据宿主的真实生命周期增加采集。

## 验证方法

解释器为独立 CPython 3.14.10，依赖按当前锁文件离线安装。所有验证使用测试凭据、环回拒绝连接端点和任务独占目录。测试没有读取生产记忆。新核心方法使用真实文件 SQLite；消息与作业原子性、进程重开、并发重放、失效租约和删除后的迟到结算均有公开接口测试。[存储测试](<../../tests/test_conversation_store.py>) · [HTTP 测试](<../../tests/test_conversation_api.py>) · [迁移测试](<../../tests/test_conversation_migration.py>)

新增模型与默认关闭开关曾先录得 3 项失败，随后实现转绿。旧库回放与归因相关定向批次 28 项通过，扩展集成批次 135 项通过，最终候选预检 59 项通过。各批次范围不同，计数不累加。Ruff 检查、格式检查与遗忘质量检查通过。

离线 wheel 已从冻结候选构建。解包加载实际应用后，在独立 SQLite 中使用真实库内 Bearer 凭据验证 schema 47、默认关闭、显式保存、Markdown 下载、删除和重放。验证进程审计限制了可打开的数据库路径与网络连接。

## 审查与修正

### Standards

公开路由的 docstring 已补齐。租约测试改用可控时钟和事件同步，保留真实 SQLite 锁和线程交错，不依赖两秒真实时钟窗口。最终静态复核确认原两项发现已解决。

### Spec

以下问题均由失败测试复现并修正，静态复核未发现原问题遗留：

- 环境服务密钥的保留身份与同名普通 Bearer 身份冲突。
- SQL DEBUG 结果行复制原文及作业令牌。
- 认领等待 SQLite 读锁期间消耗新租期。
- 功能关闭仍生成落库遥测。
- 真实认证晚于正文解析，或没有实际请求字节预算。
- 来源标签中的已知密钥形状未与正文一起检查。
