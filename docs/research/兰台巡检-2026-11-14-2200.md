## 建议

### P1-1：票 83 裁剪的理由和 ADR-0002 相反，建议改回来并统一标 `xfail(strict=True)`（约 0.5 小时）

核实到的事实：

- `docs/adr/0002-zero-hardcoding.md` 是“零硬编码策略”，决策 §1 写的是“外部脚本/工具变量：加 `REMEMBRANCE_` 前缀”。`REMEMBRANCE_PROD_HOME` 正是这一条要的形式；和 ADR-0002 冲突的是脚本里写死的 Windows 生产库路径。
- 票 83 自己的 `tests/test_ticket83_script_hardcode_residue.py::test_scripts_do_not_embed_machine_specific_homes_or_fallback_secrets` 在 CI 上点名了 `scripts/memprobe_server_main.py:25:machine-home`，就是这次说要“对齐”的那一行。
- 同一文件里留下的 3 条红测 `test_lme_double_gate_rejects_equal_home`、`test_microverify_double_gate_rejects_equal_home`、`test_adapter_double_gate_rejects_production_home_overlap`，都是先 `setenv("REMEMBRANCE_PROD_HOME", ...)` 再期待 `SystemExit("双闸失败")`，依赖的正是被删的方向。等票 83 收口，另外三个脚本会被测试逼着改读环境变量，server_main 却没有。
- 删完后 `git grep memprobe_server_main -- tests` 一条都没有，server_main 的双闸现在没有任何测试。
- 复现：在 master 上把 `LANTAI_HOME` 和 `REMEMBRANCE_PROD_HOME` 设成同一个目录，调 `memprobe_server_main._assert_double_gate()`，输出 `[双闸通过]`，没有拒启。在 Linux 上，写死的 Windows 路径经 `Path.resolve()` 会变成“当前目录 + 那串字符”，CI 和 Docker 里这道闸永远比不中。

建议做法（`tests/test_ticket83_eval_isolation.py`、`tests/test_ticket83_script_hardcode_residue.py`）：

1. `git revert fc4fb2c8`，恢复 2 条 server_main 测试和 3 条透传断言。

3. 给所有票 83 红测加 `@pytest.mark.xfail(strict=True, reason="票83：脚本改读 REMEMBRANCE_PROD_HOME / API_KEY fail-closed 后转绿")`。实现做好、测试转绿时会报 XPASS 失败，提醒你删标记，契约不会丢。

- 这是修上面那条测试时顺带发现的，本 PR 没改。`POST /conflicts/arbitrate-deep`（`lantai/api/routes_conflicts.py:64`）走的是 `CanshangEngine.arbitrate_deep_conflict`。
