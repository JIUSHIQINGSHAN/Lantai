## 回归 1：无预算时也传 timeout，评测静默变成纯关键词

- 位置：`lantai/retrieval/hybrid.py`，向量通道调 `embed([query], timeout=budget_s)`，引入提交 `a1b7a253`。
- 问题：`budget_s` 为 `None` 时也传 `timeout=None`。被 patch 到 `hybrid.embed` 上的单参实现会抛 `TypeError`，被下一行的 `except` 吞掉，只留一条「Vector search failed, falling back to keyword」告警。
- 影响：`lantai/eval/deterministic_embed.py` 的 `embed_for_eval(texts)` 就是单参，`lantai/eval/deterministic_env.py` 把它 patch 到 `lantai.retrieval.hybrid.embed`。`scripts/run_e1_e2_formal.py`、`scripts/reconcile_staged_labels.py` 都用这个环境。按代码路径，v0.65 之后跑出来的这些评测数字都没有向量通道。我没有跑这两个脚本本身，是按代码和 CI 日志推的。
- 证据：CI 日志 `Vector search failed, falling back to keyword (Shiyi): _hash_embed() got an unexpected keyword argument 'timeout'`。
- 修法：只在给了预算时才传 `timeout`；`embed_for_eval` 也接受 `timeout` 参数。

## 回归 2：预算模式下 embed 和 rerank 还在重试，超过 2 秒预算

`a1b7a253` 的提交信息和 `embed` 的 docstring 都写了「预算模式下不做多次重试」，实际没做到：

- `lantai/llm/client.py`：`@retry(stop_after_attempt(3), wait_exponential(min=1, max=10))` 直接装在 `embed` 上，预算分支也在里面。另外 `client.with_options(timeout=...)` 没关 OpenAI SDK 自带的默认 2 次重试。
- 实测：让 embedding 服务一直报错，调 `embed(["x"], timeout=0.1)`，发了 3 次请求，耗时 3.54 秒。注入帧预算是 2 秒，所以 embedding 服务一慢，就不是「向量快速失败、走关键词兜底」，而是整段检索撞外墙、只剩画像。后台线程还会继续占着 LLM 并发闸。
- `lantai/retrieval/reranker.py`：给了 `timeout` 仍然是「请求 + sleep(RERANKER_RETRY_DELAY) + 再请求」，剩余预算 1.6 秒时最坏 4.2 秒。
- 修法：tenacity 只包无预算路径（新增 `_embed_with_retry`）；预算模式 `with_options(timeout=..., max_retries=0)`；rerank 给了 `timeout` 只试一次、不 sleep。无预算的调用行为不变。

## 回归 3：X-09 写死 api.openai.com，推荐配置下精排被静默关掉

- 位置：`lantai/retrieval/reranker.py`，引入提交 `471666af`。
- 问题：没配 `RERANKER_API_KEY` 时，只有精排 host 是 `api.openai.com` 才回退用 `OPENAI_API_KEY`。可 `.env.example` 推荐的就是 `OPENAI_BASE_URL=https://api.siliconflow.cn/v1` 加 `EMBED_MODEL=BAAI/bge-m3`，还写了 `RERANKER_ENABLED=true`，却没有 `RERANKER_API_KEY` 这一项。按它配的人，`OPENAI_API_KEY` 本来就是硅基流密钥，精排也在硅基流，回退不会外发密钥，但现在精排每次都被跳过，只在日志留一条 warning。再加上 D-03 的分路阈值，注入会一直走 RRF 阈值那条路。
- 修法：同一服务商按 `OPENAI_BASE_URL` 的实际 host 判定。两边 host 一致才回退，不一致（例如 OpenAI 密钥配硅基流精排）仍然跳过，原来的防泄漏测试 `tests/test_reranker_key_leak_guard.py` 照样通过。
- 顺带：`tests/test_reranker.py` 的 `TestRerank`、`tests/test_rerank_index_and_schema.py` 测的是请求和解析主路径，显式给了精排专用密钥。
