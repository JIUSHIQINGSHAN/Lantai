# 兰台多客户端（Claude Code 及通用客户端）记忆适配方案与集成指南

> 日期：2026-11-24
> 范围：Claude Code 深度适配 + 常见 AI 编程客户端（Cursor / VS Code Copilot / Cline / Roo Code / Continue / Codex CLI / Gemini CLI 等）的通用接入
> 证据口径：本机实测（Claude Code 2.1.330、Codex CLI 0.171.0、兰台 v0.69.1 检出）与官方文档一手核对分开标注；未实测的一律标「未实测」，不写成结论。
> 结论先行：**MCP 是通用接入面（所有客户端同一份 stdio 契约），事件钩子只在提供钩子入口的宿主上做增强；兰台现有钩子适配层有一个会静默丢掉注入的真缺陷（事件名），必须按事件而不是按宿主翻译。**

---

## 一、结论摘要（可直接照着做）

1. **跨客户端只用一条主通道**：兰台现役 MCP stdio server（`python -m lantai.cli.mcp`，或装好的 `lantai-mcp`），默认档 6 个工具，`LANTAI_MCP_PROFILE=full` 放开 96 个。所有支持 MCP 的客户端都接这一条，差别只在配置文件位置和 JSON 形状。
2. **远程部署只加一层桥**：`lantai-mcp-bridge`（HTTPS REST 转发），客户端仍按 stdio 配。兰台**没有** HTTP/Streamable MCP 端点，别把 `url` 直接指向兰台。
3. **钩子只在有钩子入口的宿主上开**：Claude Code（`SessionStart`/`UserPromptSubmit`）与 Codex CLI（`hooks.json`）已有兰台适配；**Cursor 已提供钩子（本仓文档写「无命令钩子」已过期）**；Cline/Continue/VS Code Copilot 只走 MCP。
4. **两个必须先修的硬问题**（都已在真机复现，详见 §五）：
   - 兰台对 Claude Code 的所有注入帧都用 `hookEventName: "UserPromptSubmit"`，而 CC 2.1.330 会**强校验事件名，不一致整帧丢弃** → `SessionStart` 的底本注入从来没到达过模型。
   - 钩子默认 2s 预算，本机冷启动 2.5–4.8s → **默认配置下每轮检索都被超时降级**，只剩画像兜底，`event_id` 也没有（回执链断）。
5. **按本文的包装脚本 + 预算配置**，CC 真机会话里「SessionStart 底本」与「每轮检索注入」都已实证到达模型（§六.1 有会话实录）。

## 二、验证环境与证据等级

| 结论 | 证据等级 | 依据 |
|---|---|---|
| CC 钩子事件名强校验，不一致整帧丢弃 | **真机实测** | 2.1.330：同一条钩子返回 `hookEventName: UserPromptSubmit` 时，问模型「上下文里有没有 PROBE-MARKER-WRONG」答 **NO**；改成 `SessionStart` 后答 **YES** |

| CC 调用 MCP 只带 `_meta.{claudecode/toolUseId, progressToken}` | **真机实测** | 假 MCP server 抓帧；**没有** `io.lantai/attribution`，即 CC 侧无法逐调用给兰台会话归因 |

| Gemini CLI | 未核实 | 本机二进制启动即报错，未测 |

## 三、统一接入架构

```
                    ┌────────────────────── 读（每轮注入 / 会话底本） ─────────────────────┐
Claude Code ──hooks──┤  shell_hook.py（事件感知包装）→ RetrievalEvent + additionalContext │
Codex CLI  ──hooks──┤                                                                     │
Cursor     ──hooks──┘（仅 sessionStart 支持 additional_context）                           │
                                                                                         ▼
所有客户端 ──MCP stdio──► lantai.cli.mcp（本地库） ─┬─ SQLite + FTS5 ─► 记忆库/候选/提案/底本
                         或 lantai-mcp-bridge（HTTPS REST）┘
                    └────────────────────── 写（模型自主调用） ─────────────────────────┘
```

三条通道、一份契约：

| 通道 | 用途 | 谁提供 | 可靠性边界 |
|---|---|---|---|
| **MCP stdio** | 读检索、写记忆、待审、冲突、底本、回执；模型在推理循环里自主调用 | 兰台 `lantai.cli.mcp` | 协议标准、跨客户端通用；受各客户端工具审批影响 |
| **事件钩子**（命令型） | 每轮自动注入上下文 + 会话底本 + 回执/否决 | 兰台 `scripts/shell_hook.py` | 需要宿主有命令钩子；注入形状随宿主而异 |
| **REST**（`/dialogue/async` 等） | 宿主侧后台静默写对话、外部系统集成 | 兰台 FastAPI | 需要凭据与传输安全；远程部署必须 HTTPS 或 SSH 隧道 |

**写读分工不变**（README 口径）：读走钩子（快、自动），写走 MCP/REST（需模型或被采集方主动提交）。

## 四、兰台侧现状（实测契约）

- 入口：`python -m lantai.cli.mcp`（console script `lantai-mcp`）；协议 `2024-11-05`；`initialize`/`ping`/`tools/list`/`tools/call` 均已验。
- 工具档位 fail-closed：不设 `LANTAI_MCP_PROFILE` → 6 工具（`search`/`add`/`feedback`/`offload_read`/`mem_recent`/`core_memory_get`）；显式 `full` → 96。
- 归因：MCP `tools/call` 支持 `params._meta["io.lantai/attribution"]`（`version/request_session_id/request_id`），只对 `add/raw_add/search/add_dialogue/dialogue_add_async` 生效；它是**不可信标签**，不授身份、不改读域。
- 远程桥：`lantai-mcp-bridge` 只收 HTTPS（本地调试须字面量 `127.0.0.1` + `LANTAI_BRIDGE_ALLOW_LOOPBACK_HTTP=1`）；凭据用 `LANTAI_BRIDGE_BEARER_TOKEN` 或 `LANTAI_BRIDGE_API_KEY` 之一，别进命令行。
- 钩子协议：NDJSON，动作 `query`/`dialogue`/`backfill`/`retrieval_veto`/`checkpoint`/`checkpoint_write`；`query` 2s、`dialogue` 30s 预算；异常静默降级。权威描述见 `docs/host-hook-protocol.md`。
- 底本五段键名是 `cp_active_intent`/`cp_next_action`/`cp_current_work`/`cp_key_decisions`/`cp_open_notes`（不是 `identity/task/...`；用错键整批拒绝，实测 `status=rejected`）。
- 注入预算：单条 ≤200 字、总量 ≤1500 字，远低于 CC `additionalContext` 的 10,000 字上限，天然安全。

## 五、必须先修的两个真问题（含根因与改法）

### 5.1 事件名：按宿主翻译是错的，必须按事件翻译

- **现象**：`SessionStart` 注入到不了模型。CC 2.1.330 对 `hookSpecificOutput.hookEventName` 强校验，不一致时整帧视为错误丢弃（二进制内含 `Hook returned incorrect event name: expected '...' but got '...'`；真机对照实验见 §二）。
- **根因**：`lantai/integrations/host_adapters.py` 的 `HOST_EVENT = {"claude-code": "UserPromptSubmit", "codex": "UserPromptSubmit"}` 按宿主写死；`host_protocol.HostRequest` 不携带 `hook_event_name`，适配层无从知道这一帧是哪个事件触发的。
- **修法（建议票）**：`HostRequest` 增加 `event: str`（从 stdin 的 `hook_event_name` 取）；`adapt_response(host, result, event)` 用 `event` 而非 `HOST_EVENT[host]`；事件不在注入型白名单（`SessionStart`/`UserPromptSubmit`）时不包装。测试补「SessionStart 帧 → hookEventName==SessionStart」「Stop 帧 → 不注入画像」两条。
- **过渡方案（本文附带，已实测）**：宿主侧薄包装脚本，先以「直通兰台自有形状」调用 hook，再按真实事件名重包。见附录 A。

### 5.2 预算：默认 2s 撑不住 Windows 冷启动

- **现象**：CC 每个事件都新起进程；本机冷启动（jieba + chromadb + 进程导入）2.5–3.6s，走真实嵌入网关 4.7–4.8s。默认 `SHELL_HOOK_TIMEOUT=2` → 每轮都走超时降级（只有画像、无 `event_id`）。
- **改法**：
  - CC 侧：`SHELL_HOOK_TIMEOUT=8`（CC `UserPromptSubmit` 钩子默认 30s 预算，放得下）；SessionStart 事件本身没有严格超时，但保持 8s 内。
  - 若要更低延迟：给兰台加常驻 `--serve` 守护 + 宿主侧一次性连接（热进程实测 0.01–0.02s/次），但这是后续工程，不是配置能解决的。
  - 不要靠「反正有画像兜底」掩盖：兜底帧**没有 `event_id`**，回执链与否决链在这条路上直接断掉。

### 5.3 归因缺口（设计限制，不是 bug）

CC 不发送 `io.lantai/attribution`（实测 `_meta` 只有 `claudecode/toolUseId` 与 `progressToken`）。因此 CC 里 MCP 侧的 `session_id` 只能来自：
1. 模型显式传参（它不知道 CC 的 session_id）；
2. 钩子把会话标识落到本地文件，MCP server 启动时读（**拟议，未实现**：`UserPromptSubmit` 写 `<project>/.claude/.lantai_session`，MCP 进程按 cwd 读取作为默认 `session_id`）；
3. 不传——检索事件落空会话标识，写线活性判据「带 session 的读才算真实会话读」失效。

建议按方案 2 立项，并且**只在本地 stdio 形态启用**（远程桥没有可信的本地文件域）。

### 5.4 文档口径过期（如实登记）

`docs/host-hook-protocol.md` §4 写「Cursor 无命令钩子 → 降级档」，依据是 2026-09-25 的调研。当前 Cursor 已提供 `hooks.json`（`sessionStart` 支持 `additional_context`、`beforeSubmitPrompt` 只能放行/阻断）。**建议把 Cursor 从「降级档」改为「钩子档（仅会话级注入）+ MCP」**，并同步 ADR-0051 的「当前契约」表述（ADR 本身按惯例不追溯改写，改协议文档即可）。

## 六、逐客户端接入指南

> 所有示例中的 `兰台仓库路径`、`数据目录`、`venv 的 python.exe` 按本机替换。Windows 路径一律正斜杠，避免 `python -c` 里的转义陷阱。

### 6.1 Claude Code（深度适配，已真机验证）

#### 6.1.1 MCP

```powershell
claude mcp add lantai -s user -- "D:/Programs/Python312/python.exe" -m lantai.cli.mcp
# 需要全量工具面时，先设置环境变量再启动 CC：
$env:LANTAI_MCP_PROFILE="full"
```

已验证：`claude mcp list` 显示 `✔ Connected`；`initialize` 返回 `lantai`。若机器上已有旧条目指向远程桥（如本机的 `D:/Hermes/scripts/lantai_mcp_bridge.py`），先 `claude mcp get lantai` 确认，再决定保留远程还是改本地。

#### 6.1.2 钩子（推荐用事件感知包装）

`.claude/settings.json`（项目级）或 `~/.claude/settings.json`（全局）：

```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear|compact|fork",
        "hooks": [{ "type": "command", "command": "D:/Programs/Python312/python.exe D:/path/to/lantai_cc_hook.py", "timeout": 20 }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "D:/Programs/Python312/python.exe D:/path/to/lantai_cc_hook.py", "timeout": 20 }] }
    ]
  }
}
```

- 包装脚本见附录 A；它只接管 `SessionStart`（读底本）与 `UserPromptSubmit`（按 `prompt` 检索），其余事件直接退出——**尤其 `Stop` 不要接**：兰台对任何无 `prompt` 的帧都会回落成空查询并返回画像帧，接上 `Stop`/`SessionEnd` 只会往上下文里灌无意义重复。
- 必须给钩子进程设置：`LANTAI_HOME`、`API_KEY`（缺少时 `shell_hook` 直接拒绝运行，禁止 DEV 回退）、`SHELL_HOOK_TIMEOUT=8`、`PYTHONIOENCODING=utf-8`。
- 写路径：`backfill` 需要 `event_id`。用包装脚本时它作为顶层兄弟字段带出，CC 会忽略未知顶层键；宿主侧要留一个 `Stop`/`SessionEnd` 的薄脚本捕获并回填（**未实现，拟议**）。
- 对话沉淀：`UserPromptSubmit` 里同时发 `{"type":"dialogue",...}` 会走 LLM 提取，30s 预算，与每轮注入抢时间，不建议同进程做；更稳的是宿主侧异步进程或 `POST /dialogue/async`（见 §6.1.4）。

#### 6.1.3 插件形态（打包给出）

若想「装一次、自带钩子与 MCP」，按插件标准布局：

```
lantai-client/
├── .claude-plugin/plugin.json     # name/version/description
├── hooks/hooks.json               # 事件 → 命令（用 ${CLAUDE_PLUGIN_ROOT}/scripts/...）
├── scripts/lantai_cc_hook.py      # 附录 A，内部用 CLAUDE_PLUGIN_ROOT 定位
└── .mcp.json                      # mcpServers.lantai → python -m lantai.cli.mcp
```

`plugin.json` 里 `userConfig` 可声明 `lantai_home`（`directory`）、`api_key`（`sensitive`），钩子用 `CLAUDE_PLUGIN_OPTION_<KEY>` 读取；**不要**在 shell 形式命令里用 `${user_config.*}`（会被拒绝）。本地安装：`claude plugin validate ./lantai-client` → 通过后按插件目录加载。

#### 6.1.4 会话沉淀的两种正确姿势

- **异步 REST**（推荐）：宿主侧采集到用户原话后 `POST /dialogue/async`，带 `session_id` 与稳定 `idempotency_key`；兰台立即返回 `task_id`，后台提纯。CC 钩子里不要等它完成。
- **模型侧 MCP**：让模型在确认新事实时调 `add` 或 `dialogue_add_async`（默认档已含 `add`；`dialogue_add_async` 需 full 档）。

### 6.2 Cursor（MCP + 会话级钩子）

`.cursor/mcp.json`（项目）或 `~/.cursor/mcp.json`（全局）：

```json
{
  "mcpServers": {
    "lantai": {
      "command": "D:/Programs/Python312/python.exe",
      "args": ["-m", "lantai.cli.mcp"],
      "env": { "LANTAI_HOME": "D:/path/to/data", "LANTAI_MCP_PROFILE": "full" }
    }
  }
}
```

钩子（`<project>/.cursor/hooks.json`，命令从项目根执行）：

```json
{
  "version": 1,
  "hooks": {
    "sessionStart": [{ "command": "D:/Programs/Python312/python.exe .cursor/hooks/lantai_session.py", "timeout": 20 }]
  }
}
```

- Cursor 的 `sessionStart` 可回 `{ "additional_context": "..." }`；`beforeSubmitPrompt` **只支持** `continue`/`user_message`，**没有**注入字段 → 每轮检索注入在 Cursor 上做不到，只能会话开头注入底本 + 让模型用 MCP `search` 主动查。
- 脚本收到的是 `conversation_id`/`session_id`/`workspace_roots`，拿它当兰台 `session_id` 即可（`sessionStart` 有 `session_id`；`beforeSubmitPrompt` 没有，只有 `conversation_id`）。
- 输出键名是蛇形 `additional_context`，不是 CC 的 `additionalContext` —— **不能复用同一个包装脚本**，按宿主各写一层薄映射（这正是「按事件+按宿主」双重映射的必要性）。

### 6.3 VS Code（Copilot）

`.vscode/mcp.json`（编辑器管理格式，注意是 `servers` 不是 `mcpServers`）：

```json
{
  "servers": {
    "lantai": {
      "type": "stdio",
      "command": "D:/Programs/Python312/python.exe",
      "args": ["-m", "lantai.cli.mcp"],
      "env": { "LANTAI_HOME": "D:/path/to/data" }
    }
  }
}
```

Copilot 原生配置另外认工作区根 `.mcp.json`（`mcpServers` 形状）与 `$COPILOT_HOME/mcp-config.json`。VS Code 目前没有等价于 CC 的命令钩子注入通道（文档未载），所以按「MCP + 说明文件」降级：在 `.github/copilot-instructions.md` 或 `AGENTS.md` 写「需要历史上下文时先调 `lantai` 的 `search`」。

### 6.4 Cline / Roo Code

Cline：`~/.cline/data/settings/cline_mcp_settings.json`（或 IDE 里 MCP Servers → Configure），形状同 Cursor 的 `mcpServers`，远程加 `"type": "streamableHttp"`（兰台没有 HTTP MCP 端点，远程要走 stdio 桥，见 §6.8）。

```json
{
  "mcpServers": {
    "lantai": {
      "command": "D:/Programs/Python312/python.exe",
      "args": ["-m", "lantai.cli.mcp"],
      "env": { "LANTAI_HOME": "D:/path/to/data", "LANTAI_MCP_PROFILE": "full" },
      "disabled": false,
      "autoApprove": ["search", "mem_recent", "core_memory_get"]
    }
  }
}
```

Roo Code 与 Cline 同源、配置项基本兼容（**未实测**，按同形状试配）。二者都只把 MCP 工具暴露给 agent 模式，规则文件（`.clinerules` / `.roorules`）可写「先 search 再答」的静态提示。

> 安全提示：`autoApprove` 只放只读工具；`add`/`raw_add`/`rollback` 不要自动批准。

### 6.5 Continue

`~/.continue/config.yaml`（YAML 列表，不是 JSON）：

```yaml
mcpServers:
  - name: lantai
    command: D:/Programs/Python312/python.exe
    args:
      - -m
      - lantai.cli.mcp
    env:
      LANTAI_HOME: D:/path/to/data
```

MCP **仅 agent 模式可用**（文档口径）。会话级钩子：无。

### 6.6 Codex CLI

MCP（`~/.codex/config.toml`）：

```toml
[mcp_servers.lantai]
command = "D:/Programs/Python312/python.exe"
args = ["-m", "lantai.cli.mcp"]
```

本机已有 `[mcp_servers.lantai]` 指向远程桥，接本地时改名区分，别覆盖。

## 七、统一适配契约（接新客户端时照这张表）

| 环节 | 通用要求 | 常见坑 |
|---|---|---|
| 注入事件名 | 回帧的事件名 **必须等于** 触发事件名 | CC 强校验、整帧丢弃；Cursor 用蛇形 `additional_context` |
| 注入字段 | 只放「事实性上下文」，不要放命令句 | 命令句会触发注入防御，被模型当指令拒绝 |
| 输入映射 | `prompt`/`message`/`query` 三者回退；Cursor 用 `prompt`，CC 用 `prompt` | 事件不带 prompt 时**不要**发 `dialogue`/空查询 |
| 会话标识 | 优先宿主自带的 `session_id`/`conversation_id`；没有就落本地文件供 MCP 读取 | 会话标识缺失 → 回执链与写线活性判据失效 |
| 预算 | 冷启动宿主按 6–8s；常驻宿主可回 2s | Windows 冷启动 2.5s+，2s 必超时 |
| 失败降级 | 任何异常返回空输出/退出 0，绝不拖垮宿主 | 写路径结果不要包成 additionalContext（会抹掉 `receipt_status`） |
| 写路径 | 异步优先（`/dialogue/async` + 幂等键）；同步写会堵住宿主事件 | 超时 ≠ 未写入，重试前先查任务状态 |
| 权限 | MCP 工具审批按客户端配；只读工具可自动批准 | 别把 `rollback`/`raw_add` 放进 autoApprove |

## 附录 A：Claude Code 事件感知包装脚本（已实测）

放在任意固定位置（插件形态下用 `scripts/lantai_cc_hook.py`）：

```python
"""把兰台钩子响应按「真实触发事件」重包后再交给 Claude Code。

原因：兰台 host_adapters 按宿主固定写 UserPromptSubmit，而 CC 2.1.330 强校验
hookEventName，不一致即整帧丢弃（SessionStart 底本因此从未注入成功）。
"""
import json, os, subprocess, sys

HOOK = r"D:/Projects/记忆/scripts/shell_hook.py"   # 按本机改
PY   = r"D:/Programs/Python312/python.exe"          # 按本机改

def run_frame(frame):
    env = dict(os.environ)
    env.pop("LANTAI_HOST", None)          # 直通兰台自有形状
    env["PYTHONIOENCODING"] = "utf-8"
    env["PYTHONUTF8"] = "1"
    p = subprocess.run([PY, HOOK],
                       input=json.dumps(frame, ensure_ascii=False).encode("utf-8"),
                       capture_output=True, env=env, timeout=25)
    return json.loads(p.stdout.decode("utf-8") or "{}")

def main():
    try:
        raw = json.loads(sys.stdin.buffer.read().decode("utf-8") or "{}")
    except Exception:
        return 0
    event = str(raw.get("hook_event_name", ""))
    if event == "SessionStart":
        result = run_frame({"type": "checkpoint"})
    elif event == "UserPromptSubmit":
        result = run_frame({"query": raw.get("prompt", ""),
                            "session_id": raw.get("session_id", "")})
    else:
        return 0                          # Stop / SessionEnd 一律不接
    ctx = result.get("context") or ""
    if not ctx:
        return 0
    out = {"hookSpecificOutput": {"hookEventName": event, "additionalContext": ctx}}
    for k in ("event_id", "request_id"):
        if result.get(k):
            out[k] = result[k]
    sys.stdout.buffer.write(json.dumps(out, ensure_ascii=False).encode("utf-8"))
    return 0

if __name__ == "__main__":
    sys.exit(main())
```
