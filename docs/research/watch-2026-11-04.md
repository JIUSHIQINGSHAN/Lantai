### `9bea9402` 隐私绊线：root 身份下假红（本 PR 修复）

- 位置：`tests/test_repo_privacy_tripwire.py` 的 `_identity_needles()`。
- 原因：绊线把导入期的 `Path.home()` 当作本机身份，生成 `/home/<用户>`、`/Users/<用户>`、home 原文等 needle。以 root 跑时 home 是 `/root`，用户名是 `root`，needle 里就有裸的 `/root`，会命中仓库里的普通英文。
- 复现（在 `c6214c06` 上）：`HOME=/root python -m pytest tests/test_repo_privacy_tripwire.py` → `1 failed, 4 passed`，点名 5 个文件：`docs/benchmarks/e1e2-formal-2026-10/lang-drift-2026-10/EXPERIMENT.md:53`、`docs/benchmarks/e1e2-lang-drift-2026-10/REVISION-E1-LANGUAGE-LOCK.md:9`、`docs/benchmarks/selfproof-report-2026-10.md:65`、`docs/research/memory-reflection-borrow.md:106`、`lantai/llm/prompts.py:18`。命中的都是 `.../root-cause-exp.jsonl` 和 `bucket/root 摘要` 这类正文。
- 影响：你在 Windows 上跑不会触发。但只要在 Docker 容器里、devcontainer 里或用 `sudo` 跑全量，门禁就会因为这条假红判 FAIL。这类环境差正是上一轮 CI 三个失败的来源。
- 修法：对不承载个人身份的系统账户（目前只有 `root`），needle 只认带尾分隔符的 home 路径：`/root`、`/home/root`、`/Users/root`、`C:\Users\root` 四种写法后面都必须紧跟分隔符才算命中。真写进仓库的 root home 子路径照样会被抓住，正文里的 root 单词不再误伤。这不是 skip，判定对象还在。普通账户的 needle 一字不变。
- 顺手把扫描逻辑抽成 `_scan_blob()` 和 `_scan_tracked_files()`，绊线本身的行为不变，新测试复用同一份读法。

## 新建议

### P1：git 历史里的本机用户名要不要清洗，由你拍板（约半天，人工闸门）

和 §6.16 的 `.scratch/` 历史一样，只能靠 `git filter-repo` 之类改写历史再强推，所有 tag 都要重打，GitHub 上已有的 fork（包括小号的 jiushiqingshand-dev/Lantai）也要同步或删掉重建。建议先在门禁文档 §6 补登这一条，和 §6.16 合并成一次历史清洗来做。如果决定不清洗，也请在 X-05 的判定里写明「历史残留已知、接受」，别让「字面处方全部已成立」读起来像已经闭合。

### P2：绊线只防当前机器的身份（约半天）

绊线每次只扫跑测试那台机器的用户名。`PROD_LANTAI_HOMES` 里还保留着另一台机器的 `C:\Users\Asus\...`，`.scratch/` 里也有 `C:\Users\Asus\Desktop\记忆`，在你现在这台电脑和 CI 上都不会被扫到。可以在测试里放一份历史身份的 sha256 摘要，按路径段比对，这样不用把名字本身写进仓库。

### P2：门禁的 N-07 可以直接取 CI 证据（约 1 小时）

续21 到续23 都写「本机无 gh/凭据，CI 结果无证据」。GitHub 公开仓库的 Actions 结果不需要凭据也能读（`https://api.github.com/repos/JIUSHIQINGSHAN/Lantai/actions/runs?head_sha=<sha>`；这次用不带凭据的 curl 查 `c6214c06`，返回 Tests success），`release_check.py` 可以加一项按候选 HEAD 查 Tests 的结论，取不到就判红。
