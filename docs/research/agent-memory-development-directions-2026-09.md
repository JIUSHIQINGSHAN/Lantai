## 一、定位与证据边界

**建议定位：面向个人维护与多宿主 Agent 的、可追溯、可纠错、可撤回的本地长期记忆层；先证明可靠，再增加自主性。**

本地定位依据为根目录 `CONTEXT.md` 与 `docs/research/upstream-v212-gap-analysis.md`：兰台覆盖摄取、闸门、演化、检索、遗忘，已有候选、冲突、来源和诊断等概念。SQLite/FTS/Chroma 是本次用户给定的维护约束，不为追逐竞品重建基础设施。本报告不登记新功能名。

**内部事实仅继承任务交接，未重跑验证**：前次全量为 **984 passed、5 failed**，独立两文件为 **8 passed**；安全扫描 **finding 0，但 partial/inconclusive**；Hermes 来源存在 session/turn 断点；episode 已登记但未接评分。局部通过不等于全量通过，零发现不等于安全完整覆盖。旧 gap analysis 是历史判断，不视作当前实现清单；内部事实以另一份梳理为准。

## 二、四组产品：借鉴机制，不照搬规模

| 对象 | 文档/论文事实：解决什么问题 | 证据局限 | 对兰台的建议 |
|---|---|---|---|
| **Mem0** | 对话中抽取、组织、召回个人化记忆；提供库、自托管服务与云平台。[1] 当前迁移文档说明抽取改为单次调用、ADD-only，新旧记忆并存。[2] | 2025 论文采用提取后选择 ADD/UPDATE/DELETE/NOOP 的流程，[3] **不能当作当前 SDK 算法**。托管与开源能力也不能混写。 | 借鉴窄而稳定的写入/检索接口；追加保存不能代替冲突裁决。保留版本、来源和有效状态，不照搬自动写入策略。 |
| **Letta** | memory blocks 持久驻留上下文，可设容量、说明与 `read_only`，也能多 Agent 共享。[4] 解决“重要信息每轮可见”，不只追求向量召回。 | 页面说明机制，不证明任意宿主都会正确注入。常驻内容占上下文；共享块扩大变更影响范围。 | 小容量只读规则与按需检索分开；由宿主回执证明实际注入。共享必须显式授权，不把共享当作隔离。 |
| **Zep / Graphiti** | Graphiti 开源核心维护实体、事实边、来源 episode；旧事实失效而非删除，采用时间窗口和混合检索。[5] Zep 论文区分系统时间与事实有效时间，以 LLM 识别冲突。[6] | Zep 服务不等于 Graphiti 全套部署。图存储与模型增加维护成本；时间和冲突抽取仍会出错。论文没有直接评估全部来源关联价值。 | 优先借鉴有效区间、来源边、历史保留；先用 SQLite 表达最小关系。只有多跳评测证明必要，才考虑新增图数据库。 |
| **LangGraph / LangMem** | LangGraph 区分线程 checkpoint 与跨会话 namespace/store；写入可同步或后台。[7] LangMem 区分事实、经历、程序性记忆，提供提取与 prompt optimizer。[8] | namespace 是组织方式，不能自动视为鉴权。示例不是效果实验；自动优化提示词有行为漂移风险。 | 沿用宿主会话标识与异步状态契约；审批和索引任务保持幂等。经历先作可审计样本，程序性修改只生成待审建议。 |

**推断**：四者共同强调“形成—管理—取用”，并不存在被上述材料证明的唯一最佳架构。个人维护项目的差异化，更适合落在可解释的失败处理与治理，而非功能数量。

## 三、评测与研究：测什么，不能证明什么

- **LongMemEval**：500 个问题，覆盖信息提取、多会话推理、时间推理、知识更新、拒答；把记忆拆为索引、检索、阅读，并研究时间感知查询扩展。[9] **建议**：按能力分层抽样，记录证据召回与最终回答两套分数。它不是中文编码宿主测试，也不证明删除或权限正确。
- **LoCoMo**：机器生成结合人工编辑，使用人物设定和事件时间线；评估问答、事件摘要、多模态对话。[10] **建议**：先借鉴跨会话、时间和多跳问答，暂不扩展多模态。生成式日常对话与真实开发工作流有领域差距；不要把厂商改编子集的总分直接横比。
- **补充研究**：MemoryAgentBench 将信息分块增量输入，包含准确检索、测试时学习、长程理解、选择性遗忘；FactConsolidation 按更新顺序处理冲突。[11] 它支持增加“更新后还引用旧值吗”的测试，不代表“后写必真”，更不代表隐私删除验证。MemoryBank 探索时间衰减与召回强化，作者明确其模型简化且探索性强。[12] 借鉴可逆归档，不把遗忘曲线当作通用最优公式。

**建议评测协议**：固定题目、数据版本、模型、提示词、token 预算和随机种子；按会话逐步摄取，禁止未来轮次泄漏。比较无记忆、FTS、现有混合检索及单项改动；可行时加全上下文参考。英文公开基准与中文真实任务分开报告，不把翻译改编集冒充官方结果。人工复核分歧，LLM judge 仅辅助；登记摄取/维护/查询总成本和失败率，而非只报查询延迟。

## 四、三条主线与优先级

### 主线 A：评估驱动可靠性与宿主可观测性（P0）

**建议**：先解释或修复已知 5 项失败，不能以两文件通过替代全量门禁。建立“收到输入—候选—裁决—持久化—索引—召回—宿主实际注入”事件链；绑定 request、session、turn、memory 标识，分别统计成功、拒绝、待审、降级与失败。未知来源显式标记，不用推测补齐。

健康检查既看服务状态，也看真实宿主流量。有读零写需结合用户是否产生可记忆输入判断，避免把正常只读误报故障；后台心跳不能冒充用户活动。HTTP 200 或 `search_trace` 存在，均不能证明宿主拿到内容。

### 主线 B：来源、纠错、删除/撤回与人控写入（P0）

**建议**：先补 Hermes session/turn 断点，再谈回声抑制或任务信用。记忆关联原始依据、提取版本、变更与裁决者；低置信度、冲突和程序性规则变更进入既有待审流程，不静默修正。

区分四种操作：**纠错**保留版本，**撤回**停止使用某条主张及无其他支持的派生物，**归档**可逆退出常规检索，**删除**按范围清除内容。保留历史与隐私删除不能混为一谈。删除/撤回须覆盖 SQLite、FTS、Chroma、摘要、缓存和宿主副本；删除仅保留必要、不含正文的审计信息。备份另设保留周期和恢复后重新应用删除记录的规则，不承诺立即擦除所有介质。

权限从可信宿主身份取得，读取、写入、导出、来源下钻均校验作用域；默认拒绝跨用户/项目访问。检索正文是数据，不是高优先级指令；敏感信息避免进入外部模型与诊断日志。安全扫描覆盖不完整必须明示，不用“零发现”背书上线。

### 主线 C：时间检索与任务反馈（P1；自动演化 P2）

**建议**：先支持“现在”和“某时有效”的区别，分开记录发生/有效时间与入库时间，保留时区、精度及未知值。先做时间窗口过滤、冲突提示、当前/历史视图，不立即全图化；迟到更正不能按最近写入机械取胜。

episode 继续**影子记录、不接生产评分**：区分召回、注入、被采用和任务完成，保存模型、工具、任务难度及人工反馈。任务成功可能来自模型能力或其他工具，不能直接给全部召回记忆加分。累计样本后离线消融；不足则继续观察，参数和提示词变更仍需审批。

## 五、验收与有条件的 30/60/90 天路线

以下均为**建议阈值，不是文献定论**。仅在维护时间、样本及预算允许时推进；阶段未过门槛则顺延，不承诺工期。

| 阶段 | 优先级与产出 | 建议验收门槛 |
|---|---|---|
| **30 天** | P0：固定基线、来源与宿主诊断、权限/删除边界 | 当前分支全量测试无未解决失败；受影响核心函数具真实最小输入、不绕过内部逻辑的冒烟。至少 60 条固定用例，覆盖召回、更新、拒答、时间、删除/撤回、隔离。支持的宿主冒烟中来源可追溯率 100%；历史缺失单列。有限隔离/删除用例零泄漏，不外推为绝对安全。 |
| **60 天** | P1：时间检索及生命周期闭环 | 至少 30 条时间/更新用例，当前与历史证据选择正确率目标 ≥90%；确定性用例撤回后禁用命中为 0。证据 Recall@5 与人工回答正确率分别报告，关键类别不回退；同机同数据 P95 查询延迟较基线增幅目标 ≤20%。未达标保留旧方案。 |
| **90 天** | P1 反馈影子评估；P2 仅审批试验 | 目标积累 ≥100 个来源完整、人工可判定的有效 episode，并按任务类型分层；不足不进入调权。离线比较有/无候选改动及安全退化，报告不确定性。即使有收益，也先人工审核、可回滚小范围启用，不自动接分。 |

以上小样本只能用于发现退化；不够支持显著性或普适效果宣称。生产诊断记录需脱敏，并限制访问与保留时间。

### 不做清单

不重写 SQLite/FTS/Chroma；不为追平竞品引入图数据库集群；不先扩展多模态、跨域共享或 Agent 平台；不按召回次数自动晋升规则；不让自评直接调权；不用衰减替代删除；不把完整对话默认上传外部评测服务；不将广告、单榜总分、局部全绿或不完整安全扫描包装成质量结论。
