## 第二轮交锋要点

**站不住的（评审团自己点名）**：
- T4（改标签过变异门禁）——标签是 oracle 数据不是判定代码；改走三道门禁：证据先行、对表脚本产出标签数据文件人只审 diff、重跑对账。前提=标签外置出 staged.py。
- V3/V4 统计机器——「本地小样本、不外推」的报告穿重甲；首轮是定基线不是比大小。留零成本内核（abstention 单列、分层标描述性），判定规则一行进预注册，实现推迟。
- S3 门禁仪式——收成 push 前枚举反查+一个负样本变异验证，进 Day 15 收口清单。
- S5 后半（报告密钥 grep）——威胁模型不成立，审计员自撤。
- O2 主位（暂停 Windows 更新）——守夜人自撤，改「白天灌库」铁律，checkpoint 已把重启损失压到 ≤1 题。
- T2 原样执法器——0.5 天装不下，改 `Settings.model_fields` 全字段枚举断言+手工变异一次。
- V5 的「CI 档分数靠 BM25 撑」——效度官自纠为无数据断言，结论保留、理由改「构念不同」。

**互喷合流**：
- T3×V5 → CI 档定位「harness 复现性验证」，同种子重跑逐位一致；跨档含名次集在内禁比较；消融只在真档。
- E1×S1 → 「先闸后灌水」：三道闸成为 dogfooding 安装票的验收项，Day 1 装、Day 10 留/拆回执；守夜人补一刀——dogfooding 必须排在密钥熔断影子模式上线之后。
- S1① 误杀率 → 审计员接招三刀校准：全形模式正则（零误杀）、命中**转待审**不拒入（走锦囊既有通道，宁 miss 不脏写）、先影子后执法+只挂自动摄取路径。
- O1 二选一 → 守夜人投「只走 API 单通道」不停服：獬豸照常生效、provenance 天然成立、不掐 dogfooding 水源；审计员补刀——考卷灌进生产库=污染即注入面，独立 `LANTAI_DATA_DIR` 写死。

**新查缺（第二轮新增 6 条，全部采纳）**：金标映射保真度审计（覆盖率与 recall 同报）；票 A 提取段 3 报一致率；生产库冷备（Day 1+dogfooding 接入前各一次）；长跑可见性（状态落盘+通知+看进度命令）；票 D 影子开关排变异门禁；预注册 id 集 ⊆ 下载数据集 id 集的运行时断言。

**砍单裁决（15 天零和）**：票 E 考功转化率挪出窗口；E4 教程 GIF 推下窗；票 D 消融脚本砍（影子开关+盘点收成 1 天）；统计机器卸甲。约腾 3 天吸收新票与缓冲。**永不砍**：A/B/C 主线、F/G、三道闸、报告差值头条。

**顺序仲裁（铸尺人）**：S4 清树 → T1 修复过变异门禁 → 对表落 fixture → 正式跑测。脏工作树上跑探针必踩 getsource 行号错位；带替考后门的 harness 跑对表=拿被操纵的仪器做校准。
