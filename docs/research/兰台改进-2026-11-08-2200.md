## 问题（master `7c553374`）

1. **不过獬豸闸**：`scripts/reextract.py` 全文没有 `assert_no_prompt_injection`，也不读 `doc.meta`。`lantai/workers/ingest_worker.py` 第 54–61 行在摄取时命中獬豸会跳过建候选、给 doc 记 `xiezhi_blocked`，doc 行特意留下供审计；回填脚本把这些行当普通 doc 处理。
2. **`--apply` 重复建候选**：第 31 行 `if existing and not apply:` 只在 dry-run 时跳过已有候选的 doc，`--apply` 对全库每个 doc 都调一次 `extract_candidate` 再建一条（第 35–48 行）。`lantai/ingestion/dialogue.py`、`lantai/services/memory_service.py` 落 doc 时都会同时建候选，所以这类 doc 一定有候选；重建出来的是 `status=new`，而 `lantai/workers/evolve_worker.py` 第 48 行正是按 `status in ("new", "fastpath")` 取候选去 `decide` 和 `propose_from_candidate`，置信度够就自动 apply。等于待审、已拒的内容绕过了待审队列。新候选还不带 `user_id`。
3. **dry-run 和 --apply 口径不一致**：dry-run 跳过已有候选，`--apply` 不跳，dry-run 报的数比实际建的少。dry-run 还逐条调 LLM 提取，结果直接丢掉。
4. **少了摄取侧的另外两道**：不过 `detect_secret_shapes` / `route_secret_hits`，`SECRET_GUARD_MODE=enforce` 时带密钥形状的候选不会转待审；候选不带 `provenance`。

| 第一次 `--apply` 统计 | reextracted 4、skipped 0 | reextracted 0、skipped 3、blocked 1 |
| 第一次后候选数 | 3 → 7，4 个 doc 各多一条 `new` | 3 → 3 |
| 第二次后候选数 | 7 → 11，每个 doc 两条 `new` | 3 → 3 |
| 被拦的注入原文 | 成了 `new` 候选 | 没有候选 |

## 改法（只改 `scripts/reextract.py`）

- 已有任何候选（不论状态）的 doc 一律跳过，dry-run 和 `--apply` 同口径。脚本的定位改成写在 docstring 里的「回填」：只给没有候选的 doc 补。
- `meta["xiezhi_blocked"]` 为真直接跳过，计入 `blocked`，标记优先于重新判定。
- 没有标记的 doc 用和 `ingest_worker` 一样的闸文本（`title + 换行 + content`）过一次 `assert_no_prompt_injection`，命中跳过；`--apply` 时把标记合并写进 `meta`（整属性重赋，保留 `quality_signal` 等原有字段），dry-run 不写。
- 新建的候选带 `make_provenance(PROVENANCE_PROMPT_EXTRACT, extra={"origin_source": "reextract"})`；密钥形状命中的候选在事务提交之后交给 `route_secret_hits`，与摄取同一处真源。
- dry-run 只统计，不调 `extract_candidate`、不写库；`reextracted` 就是 `--apply` 会建的条数。`stats` 新增 `blocked` 键。

行为变化：以前有人可能把 `--apply` 当成「换了提取器以后全库重跑」来用。那条路会让同一个 doc 挂多条候选、待审内容重新进晋升，本 PR 不再支持；真要重跑提取，需要先设计好旧候选怎么作废，这个留给你拍板，本 PR 不做。

## 测试

新增 `tests/test_reextract_write_gate.py`，16 个用例：

- 獬豸：已记标记的 doc 不回填；标记优先（正文现在过得了闸也不回填）；没标记的注入 doc 被重闸拦下并补记标记；补记时保留原有 meta；载荷在标题里也拦；dry-run 不写标记。
- 只回填：已有候选（`pending_review`、`rejected`、`promoted`、`new` 四种状态参数化）不重复建；连跑两次第二次建 0 条；没候选的正常 doc 照常回填并带 provenance（对照臂）。
- dry-run：dry-run 报的数等于 `--apply` 实际建的数；dry-run 不调 LLM、不写库。
- 密钥：enforce 模式回填候选转 `pending_review`；shadow 模式保持 `new`（对照臂）。

把 `scripts/reextract.py` 换回 master 版本，16 个里 15 个失败：14 个是行为断言（多建候选、没转待审、没带 provenance、dry-run 调了 LLM 等），1 个是 `stats` 里没有 `blocked` 键；剩下 1 个是 shadow 对照臂，两边都通过。

全量：本地 `.venv`（Python 3.13）全量 3271 个通过、5 个跳过、0 个失败，用时约 6 分钟。
