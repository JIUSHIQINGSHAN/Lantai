# 兰台巡检 2026-11-20 12:00：ADR-0090 第 3 条只落到了一个桥，默认 MCP 还在说「理由可选」

提交者：Maya（Sesame 的 AI 助手），代用户经小号 jiushiqingshand-dev 提交。

## 结论

本轮审了上次巡检（e8d5c7f7）以后 master 上的 9 个新提交，到 eaa5d29a。没有发现产品回归。只有一处收口不全：

196ca173 按 ADR-0090 第 3 条，把 `lantai-mcp-bridge` 里 `conflict_resolve` 的入参改成了「理由必填、不能全是空白，decision 只能是 resolved / dismissed」。但同一个工具在另外两处还是旧的写法：

- `lantai/cli/mcp.py`（进程内 stdio MCP，Hermes 默认接的就是它；开了 full 档才暴露这个工具）
- `scripts/lantai_mcp_bridge.py`（DSH 用的桥）

这两处的 schema 还写着 `note: {"type": "string", "default": ""}`，required 里没有 note。服务层从 v0.15.2 起就要求非空白理由，所以模型照着 schema 调用、不带理由时，每次都会被拒：

```
master：required = ['event_id', 'decision']，note = {'type': 'string', 'default': ''}
不带 note       → -32602 decision reason is required
note = "   "    → -32602 decision reason is required
```

数据不会被写坏，服务层兜住了。问题在于工具说明和实际要求对不上：模型第一次调用一定失败，要靠报错文字猜出得补理由。ADR-0090 第 3 条要求的是在边界上把服务本来就不接受的调用挡掉，并把要求写进 schema，现在只有一个桥做到了。

## 改法（PR 内容）

- `lantai/cli/mcp.py`：schema 里 note 改成必填、`minLength: 1`，去掉 `default: ""`；decision 加 `enum`。处理函数在进服务层之前就拒绝空白理由，返回 -32602。
- `scripts/lantai_mcp_bridge.py`：schema 同样改过来。
- 服务层、`lantai-mcp-bridge`、REST 都没动。

修后：

```
required = ['event_id', 'decision', 'note']，note = {'type': 'string', 'minLength': 1, ...}
不带 note / 空白 → -32602 note (decision reason) must be a non-blank string（不进服务层）
```

1. 用 `LANTAI_MCP_PROFILE=full` 启动 MCP，在 tools/list 里看 `conflict_resolve`：required 里应该有 note，而且 note 没有默认值。

3. 带上理由再调用，结果应该和以前一样。
