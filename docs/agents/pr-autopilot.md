# PR 自动处理流程

当用户要求检查、处理、修复或自动推进 PR 时，按此流程执行到**可送审、可供维护者决策**的边界。每次先查当前开放 PR 与分支，不从旧对话推断状态。

## 流程

1. **发现**：获取开放 PR 编号、标题、head/base、author、review requests、conversation comments、checks 和 merge status。优先认证 CLI/MCP；不可用时查 GitHub 网页。网页/API 不可达时注明证据缺口，只用现有本地 ref 补充，不能把缓存显示当实时状态。完成条件：候选 PR 与查询时间/来源已记录；没有开放 PR 时报告为空，不改其他分支。
2. **匹配**：将用户任务与 PR 文件/标题匹配。用户给定 PR 优先；否则选最高优先级的阻塞项：维护者 change request、安全/数据风险、CI 红、冲突/落后主干，最后才是一般 review。更新审查时间较新的资料优先；平局取较小 PR 编号。工作目录有未提交修改时逐文件列出，任何文件与目标 PR 重叠就先隔离或请求维护者指导；绝不把无关修改夹带进目标 PR。
3. **建立安全工作区**：从最新目标 base 建新本地分支，使用独立 worktree；保留现工作区原样。若 worktree 无法建立，不在脏树上 checkout/switch，改为只读诊断并说明阻塞。完成条件：目标分支指向记录过的 base SHA，原工作区状态前后无损。
4. **复现与修复**：读适用 `AGENTS.md`、CONTEXT/Glossary、ADR 和 PR 对应票据。先运行最小失败测试复现所提问题，再按 TDD 修复；PR 是 test-only 时不得顺手加产品功能。只触碰目标病灶与必需测试/文档，测试遵守不 mock 核心逻辑纪律。修不了时记录失败证据，不删断言、不 skip、不改测试让其假绿。
5. **验证**：先目标测试，再相关家族、lint/format、release check 的相关只读项，最后全量测试及项目特定质量门禁。全量失败时提取每个失败的测试名、原因、是否出现在目标 base 的对照运行，并跑最小定向复现；无基线证据时标为“归因未定”，不得称预存失败。远端 CI 不可查询时明确未验证。
6. **收口**：完成独立 review，检查 diff、密钥/数据隔离、票据状态和 CHANGELOG 要求。扫描新增/修改文档中的用户名、主机名、家目录、绝对路径、凭据和用户数据；安装说明命中本机路径时先用脱敏占位符或中止并询问维护者，不推测替换路径。给出 PR 可继续审查的文件/分支、测试结果、残余风险、准确 CI 状态。未满足隐私/数据闸门时不得标为 ready-for-human 或建议合并。不得重写 PR 历史或改变无关文件。

## 外发闸门

本流程默认只准备本地 PR 分支。即使用户说“自动进行”，也不自动 push、创建 PR、提交 review/评论、批准、合并、打 tag 或发版；这些动作须有明确当轮授权。创建/更新远端 PR 前，先展示确切目标、标题/正文或将发送的评论并征得确认。不得把用户对本地修复的授权解释为远端发布授权。

## 可直接复用的自动化提示词

```text
处理当前开放 PR：先读取 docs/agents/pr-autopilot.md。发现并核对全部 open PR 的实时状态、head/base SHA、reviews/comments/checks；按 blocker 优先级选择与本任务最相关的 PR。保存当前工作树逐文件状态，任何 dirty 内容都保留。若与 PR 有重叠，在独立 worktree 从最新 base 建候选分支；复现最小故障，按 TDD 只改目标范围，运行目标测试、相关家族、lint/format、门禁对账和全量测试。全量失败逐项说明测试名、输出与是否在 base 同样失败，不得笼统归为预存。最后做独立 diff review 和本机路径/密钥扫描；安装文档含本机路径时先脱敏或列为送审阻塞。报告送审分支、测试和未验证事项。只准备本地，不 push、不发评论、不批准、不合并、不发布；除非本轮明确给出对应远端动作授权，否则停在本地候选分支。
```

## 证据模板

每次收口至少报告：目标 PR 与来源/读取时间、head/base SHA、选择理由；目标分支与隔离方式；复现命令/红相；修改文件；各项测试退出码和全量失败归类；check 状态（通过/失败/待查）；未验证项；是否执行任何外发动作。
