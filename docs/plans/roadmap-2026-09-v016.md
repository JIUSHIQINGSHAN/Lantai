# v0.16 路线计划书（2026-09）

> 目标：落实“可控记忆层”主轴，把兰台从“检索能力竞争”推进到“记忆生命周期质量竞争”。

## 一、主轴与边界

1. 产品主轴：写入准确性、冲突可审计、选择性遗忘、可回滚。
2. 定位表达：兰台是“可控记忆层”，不是通用 RAG 框架。
3. 架构边界：坚持本地优先、可审计、可迁移、轻量内嵌，不引入重托管与重依赖路线。

## 二、v0.16 近阶段优先级（下一版本）

### A. MCP 工具面与客户端矩阵扩展

- 目标：覆盖 Hermes 之外的 IDE/CLI 客户端接入与验证。
- 交付：
  - MCP 工具能力增量（围绕管理/审计/诊断闭环）
  - 客户端接入矩阵补齐（至少含 Claude Code、Cursor、Gemini CLI、Codex CLI）
  - 接入验证清单与回归用例同步
- DoD：工具契约文档、MCP 测试与客户端配置文档一致。

### B. 变化追踪可解释性增强

- 目标：打通“时间轴 + supersedes + 冲突账本”的统一解释链。
- 交付：
  - 变化轨迹查询与聚合视图
  - 冲突账本与变更关系联动展示
  - 审计字段补齐（谁/何时/为何变更）
- DoD：任一记忆可追溯“变化前后与裁决依据”。

### C. 可视化管理闭环

- 目标：把候选待审、衰减状态、checkpoint 入口纳入统一控制台操作路径。
- 交付：
  - 待审队列与提案/冲突检查器联动
  - 衰减与归档状态可视化
  - checkpoint 读取/写入/回滚入口可达
- DoD：运营人员可在单面板完成“发现问题→定位依据→执行处置”。

## 三、中期差异化（1 个大版本窗口）

### D. 记忆生命周期评测体系

- 目标：建立“遗忘质量 + 陈旧治理”的可复现指标。
- 交付：
  - 指标定义与统计脚本
  - 周期化评测报告模板
  - 版本门禁接入策略
- DoD：版本可量化比较“记忆质量”变化。

### E. 中文场景评测集与对外报告

- 目标：放大中文检索、容错、时效治理优势。
- 交付：
  - 中文样本扩容与分层标注
  - 评测结果说明与可复现实验步骤
  - 对外发布稿（含限制与未确认项）
- DoD：外部可复测，内部可复跑。

### F. 自动蒸馏与人工裁决协同

- 目标：形成“自动提炼 + 人工闸门”稳定回路。
- 交付：
  - reflect/autodream 触发与裁决策略联动
  - 高置信自动应用与中低置信待审边界复核
  - 异常/空产出可观测性加强
- DoD：自动化增益可见，且不突破“宁 miss 不脏写”。

## 四、发布与工程纪律

1. 延续“先门禁后发布”：pytest 全绿 + 质量门禁 + release_check 通过后再进入人工上传闸门。
2. 测试纪律不放松：核心函数保持至少一个不 mock 冒烟测试。
3. 文档纪律：每项行为语义变更同步 ADR/CONTEXT/CHANGELOG。

## 五、明确不做

1. 不切换到 mem0+Qdrant 一体化重依赖路线。
2. 不把重心放在“大厂原生记忆同质竞速”。
3. 不牺牲可审计性换取黑盒自动化写入速度。
