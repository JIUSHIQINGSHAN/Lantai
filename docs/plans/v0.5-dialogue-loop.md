# v0.5 方案「对话闭环」— 让记忆系统适合自己（2026-08-09）

> 由访谈收敛而来（grill-with-docs 流程，9 项决策全部用户确认）。
> 方向调整：**不再按 aiduMEM 功能对齐**，改为需求驱动——先解决"系统不为用户积累"的核心矛盾。
> aiduMEM 借鉴项降级为 backlog（见 docs/plans/v0.5-optimization-plan.md）。

## 一、访谈结论（用户决策，已确认）

| # | 决策 | 内容 |
|---|---|---|
| Q1 | 价值定位 | **主动检索**——写入是手段，不是目的 |
| Q2 | 使用方式 | Hermes 自动注入（shell_hook pre_llm_call） |
| Q3 | 核心痛点 | **不可感知**——看不见系统记住了什么 |
| Q4 | 写入源头 | **对话自动提炼**（新增写通道；现状：20 次 add vs 420 次检索） |
| Q5 | 感知方式 | **每日盘点报告** + 检索透明（用了哪些记忆） |

## 二、系统设计：五个组件

```
Hermes 对话 ──► ① Dialogue Ingest ──► 现有提取流水线（extract→gate 分层）
                                        │
                    ┌───────────────────┤
                    ▼                   ▼
              Fastpath 直通     候选（pending_review）
              （"记住"标记）        │
                                    ▼
                            ② Candidate Review Queue（TTL 7d）
                                    │ approve
                                    ▼
                            memoryproposal → memoryitem（记忆库）
                                    │
③ Daily Digest（每日盘点）◄─────────┘ + 检索统计
④ Search Transparency（注入时显示用了哪些）
```

### ① Dialogue Ingest（对话写通道）— 核心新增
- 新模块 `remembrance/ingestion/dialogue.py`：接收对话文本+元数据，复用现有
  `rawdocument → extract_candidate → gate` 链，**不新建存储**。
- 分 lane：偏好/事实/指令类自动提取（gate 7 类启发式），闲聊 reject 进队列；
  "记住/很重要"类标记走 Fastpath 直通（复用现有 fastpath 白名单）。
- 触发源（实现时验证，二选一）：
  - **A. Hermes 插件会话结束钩子**——已有 `pre_llm_call` Python 插件，验证 Hermes
    插件 API 是否提供 session 结束事件（首选，实时）
  - **B. 定时扫描 Hermes state.db 新消息**——每日批量导入（实现简单，隔日感知）
- 约束：**LLM 提取降级不阻塞**（上游 502 时候选兜底进队列，不丢数据）。

### ② Candidate Review Queue（候选可见队列）
- `memorycandidate` 加字段：`review_due_at`（TTL）；状态扩展 `pending_review`
  （reject 不再静默丢弃，改为入队）。
- REST/MCP：`GET /candidates/pending`、`POST /candidates/{id}/review`（approve/reject）。
- 每日任务：超龄（>7 天，阈值进 settings）候选归档为 rejected，digest 记录"归档 N 条"。
- 铁律更新：AGENTS.md「宁 miss 不脏写」补充——校验失败不自动修正，但**进待审队列**
  （用户决策权），超时归档。

### ③ Daily Digest（每日盘点报告）
- 新 worker（APScheduler 每日）：生成 `docs/memory-digest/YYYY-MM-DD.md`。
- 内容：新增记忆 / 修改 / 待审候选数 / 归档数 / 检索统计（次数、zero_result）。
- Hermes 早晨注入：shell_hook 首条查询附带当日 digest 摘要（或 MCP `get_digest`）。

### ④ Search Transparency（检索透明）
- shell_hook 注入文本附"本次依据"（用了哪些记忆 id/内容摘要）——event_id 已透出，
  used_ids 回填通道已有，补展示层。
- MCP search 响应已含结果，补"命中来源"说明。

### ⑤ 治理与质量
- 新阈值全部进 settings：`DIALOGUE_*` / `CANDIDATE_TTL_DAYS` / `DIGEST_*`（零硬编码）。
- ADR-0009 记录对话写通道与队列设计。
- 每个核心函数（dialogue_ingest / candidate_review / digest_build）配不 mock 冒烟测试；
  全量测试保持全绿。

## 四、验收标准

1. 对话文本进系统后：有价值内容自动进候选/直通，闲聊不落库；
2. 被拒候选可见可审，TTL 自动归档；
3. 每日 digest 生成，Hermes 早晨可读；
4. 检索注入带"依据"；全量测试全绿；无新硬编码。

## 五、风险与未决

- **Hermes 插件会话结束事件**是否存在——P2 验证，备选 state.db 扫描（跨进程读 SQLite
  需只读连接 + WAL）。
- **提取成本**：对话自动提炼会触发 LLM 提取（token 成本 + 上游不稳定）；Fastpath +
  分 lane 控制，降级兜底不丢。
- **候选队列膨胀**：TTL 归档 + digest 透明化控制。
