## 一、通用质量铁律（每项必守，不满足不入库）

1. **决策留痕**：涉及行为/语义变更先出 ADR，新命名登记 CONTEXT.md（ADR-0013 R4）。
2. **测试纪律**（AGENTS.md）：核心函数必须有**不 mock 冒烟测试**。
3. **回归门禁**：任何合并前 `pytest tests/` 全绿 + `run_forgetting_quality.py --check` PASS。
4. **发布门禁**：`release_check.py vX.Y.Z` 全 PASS 才进入人工闸门；push tag 由维护者执行。
5. **文档同步**：每项收口登记 CHANGELOG + 相关 ADR/CONTEXT/README。
6. **宁 miss 不脏写**：拿不准的判定一律保守——进提案待审、留空、延长观察窗。

## 三、v0.16.0：沙汰 + 察窗（已完成）

### 沙汰（ADR-0026）

- 闲聊（conf=0.0）→ 直接 rejected，不进待审队列
- 新增 `CANDIDATE_MIN_CONFIDENCE` 设置（默认 0.0 = 零行为变化；校准建议 0.15）
- 低于地板值的 LLM 提取候选 → 直接 rejected

### 察窗（ADR-0027）

- 观察期口径：连续 → 滑动窗口（`REFLECT_OBSERVATION_WINDOW_DAYS`=14 天内 `REFLECT_OBSERVATION_REQUIRED_RUNS`=7 天合格）
- `scripts/reflect_observation_status.py` 实现窗口计数
- 实测：4/7（14 天窗口），需 3 次合格定时运行

### 召回健康度

- `scripts/recall_health.py` 只读检查：检索总量、零召回率、系统噪音、每日趋势
- `docs/ops-runbook.md` 运维手册：服务启动、候选堆积、召回空转、观察期门禁四个场景

## 四、v0.16.1：零召回根因修复

**背景**：`recall_health.py` 实测 14 天内 23 次检索全零结果（100% 零召回率）。需要诊断：

1. 检索日志审计：`retrieval_event` 的 `result_ids`/`result_scores` 是否全空，`query_text` 是否正常
2. 向量存储健康：ChromaDB 是否加载了正确的 collection，embedding 维度是否匹配
3. FTS5 索引健康：`memory_fts` 表是否同步，trigram 分词是否落库
4. 闸门/过滤器：`prefilter` 是否过严导致全量被过滤
5. 修复方案：根据诊断结果出 ADR-0028

**验收 DoD**：① 诊断报告留档（`docs/memory-quality/zero-recall-diagnosis-YYYY-MM-DD.md`）
② 修复后 `recall_health.py` 零召回率 < 30%
③ ADR-0028 + 测试 + CHANGELOG。

## 五、v0.16.2：观察池选一

从 v0.15 观察池中选一项入 v0.16.2：

- **Persona 人格基座**（L/G/E，aiduMEI）：固定角色人格记忆层，影响检索权重与提案生成
- **refine 递归精炼**（autodream 深化）：蒸馏后的候选再经 LLM 精炼，提升置信度
- **EvolveMem 权重演化**：feedback/verification 打底后的自动权重调整
- **评测集新类别**：跨命名空间 / 多轮专类（动指标口径，需独立立项）

**选哪项由维护者决定**——Agent 不承诺。选后出 ADR + 不 mock 测试 + 门禁。
