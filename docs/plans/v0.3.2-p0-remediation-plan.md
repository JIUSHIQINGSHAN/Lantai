### 步骤 2：`remembrance/core/auth.py` 整体替换为

```python
"""API Key 鉴权依赖 + 部署绑定安全检查"""
import hmac

from fastapi import HTTPException, Header
from remembrance.core.settings import settings

LOOPBACK_HOSTS = {"127.0.0.1", "localhost", "::1"}


def assert_secure_binding() -> None:
    """非回环地址必须配置 API_KEY，否则拒绝启动（lifespan 调用）。"""
    if settings.HOST not in LOOPBACK_HOSTS and not settings.API_KEY:
        raise RuntimeError(
            f"Refusing to start: HOST={settings.HOST} is not loopback "
            "but API_KEY is empty. Set API_KEY or bind to 127.0.0.1."
        )


async def verify_api_key(
    x_api_key: str = Header(None, alias="X-API-Key"),
) -> str:
    """验证 X-API-Key header（恒时比较，防时序侧信道）"""
    if not settings.API_KEY:
        return "no-auth"

    if not x_api_key:
        raise HTTPException(status_code=401, detail="Missing X-API-Key header")

    if not hmac.compare_digest(x_api_key.encode("utf-8"),
                               settings.API_KEY.encode("utf-8")):
        raise HTTPException(status_code=403, detail="Invalid API Key")

    return x_api_key
```

注意：原文件顶部有 `from fastapi import Depends, HTTPException, Header`，`Depends` 实际未用，替换后删除；确认 `api_server.py` 中对 `verify_api_key` 的引用方式（`Depends(verify_api_key)`）不受影响。

## Wave 3（P0-3）：测试基线修正 + 2 个潜在产品 bug

问题：`test_p0.py` 经 `/search` 端点触发真实 LLM（应测 fts 层）；`resp.json` 两处缺括号；重写时又暴露 2 个产品 bug，一并修复：
- **bug-a**：`fts.py` 把字符串 memory_id 当 FTS5 INTEGER rowid 插入，必报 datatype mismatch（被静默吞掉）；且 FTS 表绑定了不存在的外部内容表结构。
- **bug-b**：`hybrid.py:78-80` 直接用 aware 的 `utcnow()` 比较从 SQLite 读出的 naive `valid_from/valid_to`，任何设了时间窗的记忆都会让检索抛 TypeError（与 Wave 5 修过的 forgetting.py 时区 bug 同类）。

### 步骤 1：修复 `remembrance/storage/fts.py`

`init_fts` 中的建表 SQL 替换为：

```python
        conn.execute("""
```

`index_fts` 的 INSERT 替换为：

```python

            "INSERT INTO memory_fts(memory_id, content) VALUES (?, ?)",

```

`search_fts` 的 SELECT 替换为：


**注意（不执行，只记录到最终报告）**：既有 `remembrance.db` 中若已存在老 schema 的 `memory_fts` 表，`CREATE IF NOT EXISTS` 不会迁移。因 FTS 当前零生产调用方、无数据，建议用户择机执行 `DROP TABLE IF EXISTS memory_fts;` 后重启服务由 `init_db` 重建。**执行者不得擅自操作用户数据库。**

### 步骤 2：修复 `remembrance/retrieval/hybrid.py` Chronos 时区

第 73–83 行（`# Step 2.5: Chronos 双时间过滤` 整段）替换为：

```python
    # Step 2.5: Chronos 双时间过滤（DB 读出的 datetime 为 naive，需先归一时区）
    from datetime import timezone
    from remembrance.core.time import utcnow
    now = utcnow()
    temporally_valid = []
    for m in items:
        vf = m.valid_from
        if vf and vf.tzinfo is None:
            vf = vf.replace(tzinfo=timezone.utc)
        vt = m.valid_to
        if vt and vt.tzinfo is None:
            vt = vt.replace(tzinfo=timezone.utc)
        if vf and vf > now:
            continue
        if vt and vt < now:
            m.decay_score *= 0.3
        temporally_valid.append(m)
    items = temporally_valid
```

```python
    mid = new_id("mem")
    with Session(engine) as s:
        s.add(MemoryItem(
            id=mid, memory_type="general", key=mid, content=content,
            lane="general", status="active", importance=0.5, use_count=0,
            decay_score=1.0, last_used_at=utcnow(), created_at=utcnow(),
            valid_from=valid_from, valid_to=valid_to))
        s.commit()
    return mid
```
