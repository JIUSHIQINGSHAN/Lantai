# v0.5 优化方案 — 借鉴 aiduMEM 的优势（2026-08-08）

> 依据：`outputs/aidumem-vs-remembrance-对比报告.md` + aiduMEM 源码静态分析
> 原则：**借鉴设计思想，不照搬代码**。aiduMEM 是 mem0/Qdrant 架构，本系统是
> SQLModel/SQLite/ChromaDB；每项移植必须遵循项目铁律（测试纪律 / 人工闸门 /
> 宁 miss 不脏写 / 零硬编码 / ADR 决策记录）。

## 一、差距对照（只列值得做的）

| aiduMEM 能力 | 实现方式 | 本系统现状 | 契合度 |
|---|---|---|---|
| Raw Drawer 原文直存 | 文本直入 FTS+向量，零 LLM，verbatim tier | 已有 FTS5+ChromaDB+MemoryItem | ★★★ 高 |
| ConflictResolver 显式消解 | 属性覆盖 + 互斥规则 + 变更账本 | 已有 Chronos+MemoryEdge supersedes+LLM 矛盾检测 | ★★★ 高 |
| SkillCrystallizer 结晶 | 高频分类聚类 → 人工审核候选 | 已有 lane + 人工闸门铁律 | ★★★ 高 |
| TreeMemory 树状组织 | memory_nodes（parent_id/node_path） | 已有 MemoryEdge 关系图 | ★★ 中 |
| MCP 工具扩容 | 38 工具 | 4 工具（search/add/feedback/backfill） | ★★ 中 |
| autodream 蒸馏 | 7 天周期提炼 | 路线图已有（未实现） | ★★ 中 |
| Code Graph 代码图谱 | ast 解析依赖图+爆炸半径 | 无 | ★ 低 |
| Pantheon 联邦 | 注册表+心跳+MoE 门控+分层衰减 | 单机单 Agent | ★ 低 |

## 二、P0（低成本高价值，先做）

### 1. Raw Drawer 原文直存（verbatim 记忆）
- **痛点**：长代码/日志/配置走 LLM 提取会被总结损失细节，且消耗 token。
- **设计**：`POST /add/raw`——内容直入 FTS5 + ChromaDB 向量，**只 embedding 不 LLM**；
  `MemoryItem.memory_type="verbatim"` 标记，不走提取/闸门/演化流水线。
- **映射到本系统**：复用 `init_fts/sync_fts` + `index_memory_item`（vector_store）；
  去重用内容 sha256（幂等）；检索自动命中（FTS trigram 子串容错天然适配原文）。
- **测试**：不 mock 冒烟——真实内存 SQLite 写入 → 检索命中 → 去重幂等 → 零 LLM 调用断言。
- **成本**：约 1 个路由 + 1 个 service 函数 + 1 个测试文件。

### 2. 冲突消解确定性层（规则层 + LLM 层双通道）
- **痛点**：现有 `contradiction.py` 仅 LLM 判断（慢、不可复现、依赖外部 API）；
  无确定性规则可解释的消解。
- **设计**：新增 `gate/conflict_rules.py`：
  - 互斥规则集（settings 可配，正则）：状态开关双向、名称更名、域名变动
  - 属性级覆盖：同 lane+同 key 旧值 → 新值写入时旧记忆打 `supersedes` 边 + Chronos 软失效
  - 变更账本表 `conflict_event`（可溯源，复用 MemoryEdge 思路）
  - 规则未命中 → 回落现有 LLM `check_contradiction`（降级不阻断）
- **映射到本系统**：`MemoryEdge(relation="supersedes")` 已有；加 `valid_to` 软失效
  与遗忘/检索降权联动（Chronos 已支持）。
- **测试**：不 mock——规则命中/未命中/账本写入/与 LLM 层降级顺序。
- **成本**：1 个规则模块 + 1 张表 + 写入链路钩子 + 测试。

## 三、P1（中成本，扩展能力）

### 3. SkillCrystallizer 记忆结晶
- 按 lane+主题聚类高频记忆（≥3 条触发，阈值进 settings）→ `skill_crystal` 候选项；
  **只有人工审核才能 approved**（与项目人工闸门铁律完全一致）。
- 输出为结构化建议（触发词/步骤摘要），不直接生成 SKILL.md。
- 接入 `evolve_worker` 定时任务 + `POST /crystals/{id}/approve`。
- 测试：聚类纯函数 + 审批状态机 + 阈值边界，不 mock。

### 4. TreeMemory 树状组织
- 轻量方案：**复用 MemoryEdge**（relation="child_of"）实现父子关系，不新建表；
  提供 `get_subtree/get_ancestors` 查询 + 树检索 boost（子节点记忆检索时父节点加分）。
- 测试：树构建/遍历/环检测，不 mock。

### 5. MCP 工具扩容
- 新增：`raw_add`（原文直存）、`conflict_resolve`（显式消解）、`crystal_list`/
  `crystal_approve`、`memory_tree`（子树查询）、`rollback`（回滚现有能力透出）。
- 保持输入校验 + 异常隔离（现有 MCP 模式）。

## 四、P2（高成本或按需）

- **autodream 蒸馏**：7 天周期从历史事件提炼长期记忆（路线图已有），依赖 P0 Raw 直存
  的 verbatim 语料，建议放 P0 之后单独规划。
- **Code Graph 代码图谱**：仅当出现"代码记忆"类使用场景时做（ast 解析依赖图可整体
  借鉴，与记忆引擎解耦）。
- **Pantheon 联邦**：单机单 Agent 场景无收益，明确不做；若未来多 Agent 再评估
  （注册表+心跳+MoE 门控思路已在本方案记录）。

## 五、明确不做

- PyPI 发布（本地项目无需求）
- 希腊神谱命名体系（风格不匹配）
- 引入 mem0/Qdrant（重量级依赖，违背轻量内嵌原则）

## 六、验收标准

- 每项功能：核心函数有不 mock 冒烟测试；全量测试保持全绿
- 新表/新字段：ADR 记录决策（0009+）
- 所有新阈值进 settings（零硬编码）
- 冲突消解/结晶等"写"路径保留人工闸门，绝无自动应用

## 七、建议排期

|---|---|---|

| P0-2 | 冲突消解确定性层 | 1 天 |
| P1 | 结晶 + 树状 + MCP 扩容 | 2-3 天 |
| P2 | autodream / 按需项 | 视需求 |
