# 兰台全自动化开发提示词（主控版）

> 用途：把下面「提示词正文」整段粘贴给你的 AI Agent，即可让它**无人值守**地
> 跑完「调研 → 立项 → TDD → 变异门禁 → 全量回归 → 提交」整条流水线。
> 唯一需要人来做的事：**push tag**（发布人工闸门）。
>
> 维护者须知：Agent 会**自主做决定、不提问**（见记忆
> `work-style-autonomous-decision-making`）。它不该回头问你任何问题；
> 遇到规格不清，它按本文档「歧义裁决」一节自己定，并把决定写进票据。
>
> 适用版本：v0.22.1 之后的工作区（1970 测试基线）。

---

## 提示词正文（从这里开始复制）

你现在接手兰台（lantai）记忆系统的**全自动开发流水线**。你的目标不是修一个
bug，而是把**当前所有未结票据**按纪律推进到可合并状态。全程自主决策，除
`git push` 外不要停下来问人。

### 0. 先读这些（不许跳过）

```
AGENTS.md                                        ← 项目铁律（测试纪律/命名纪律/发布纪律）
docs/development-workflow.md                    ← 六阶段 SOP
docs/agents/issue-tracker.md                    ← 票据格式与 Status 语义
docs/agents/triage-labels.md                    ← 五个分诊标签
CONTEXT.md                                      ← 词汇表（新名字必须先登记）
CHANGELOG.md 的 [Unreleased]                     ← 上一个票怎么写的，照这个格式
```

然后用 `grep -rl "^Status: " .scratch/*/issues/*.md` 把全库票据状态扫成一张表，
按下面规则排执行顺序：

| Status | 处理方式 |
|---|---|
| `done` | 跳过，只作为上下文读它的验收与教训 |
| `planned` | **进执行队列** |
| `ready-for-agent` | **进执行队列** |
| `needs-triage` | 先做一次分诊（判断是否真该修），再决定进不进队列 |
| `needs-info` | 缺的上下文若能自己调查补齐就补，然后升级为 `ready-for-agent` |
| `ready-for-human` | **不动**，只在结尾报告里列出并说明为什么 |
| `wontfix` | 跳过 |

执行顺序规则：
1. 依赖优先：被 `Blocked by:` 的票先做。
2. 同无依赖时，**安全洞（读侧/写侧越权）优先于功能缺陷，功能缺陷优先于 P3 观测问题**。
3. 一张票做完再开下一张。**不许并行开两张**——前一张的门禁结论会污染后一张的变异判据。

当前工作区的实际队列（2026-09-28 快照，你自己重新扫一遍核实）：

| 票据 | 优先级 | 说明 |
|---|---|---|
| `mcp-identity-gaps/08-admin-two-forms-inconsistent` | P3 | admin 两种形态行为不一致；**开工前必须先定三个待决项**（票里写了） |
| `ci-lint-gate/01` | — | CI lint 挡测试门禁 |
| `mcp-tool-parity/01` | — | MCP 工具广告与处理器对齐（`recall_chain` 保底 KeyError） |
| `proposal-target-gap/01` `02` | — | proposer/promoter 的 target 解析 |
| `expiry-exclusion/01` | — | 过期主张不退出召回 |
| `fts-null-owner/02` | — | 写侧放行 NULL 属主（结构性隐患，无现实可利用面） |

### 1. 每张票的固定流程（七步，一步不许省）

对队列里的每一张票，严格按顺序执行：

**① 立状态**：把该票 `Status:` 改成 `in-progress`，写进票据头部一行
`Started: <今天日期>`。这是给中断恢复用的锚点。

**② 先说影响**：在动手前，先在票据里写一段「先说影响」——用**非技术维护者
能懂的大白话**回答三件事：谁的数据会受影响、往坏的方向还是往"该看的没看到"
的方向、修与不修的差别。**这段是你后面所有技术判断的校准器**：如果你的修法
让这段话描述的风险没变小甚至变大，停下来重想。

**③ 根因诊断（5 步，对应 SOP 阶段 2）**：
1. **复现**：写一个最小探针脚本（放 `.scratch/<feature>/probe_*.py`），
   稳定复现问题，保留输出到 `_*.txt`。
2. **单一假设**：写出一句可证伪的假设，指明文件与行号。
   例：「假设 `memory_service.py:139` 的 `embed()` 在外部 API 401 时抛异常未被捕获」。
3. **隔离求证**：跑探针证实假设，**未求证前不许改任何业务逻辑**。
4. **最小修复**：只改根因那一处。**不许用空 `try/except` 吞异常，不许屏蔽断言**。
5. **验证回归**：专门测试 + 全量测试。

**④ 盘点影响面**（AGENTS.md「护栏要枚举不要 allowlist」）：任何改动前，先用
AST 或 grep **枚举全量**相关调用点，不许凭印象列几个。对枚举出的每一项显式
处理，并在票据里记下"枚举到 N 项，逐项去向如下"。用正则枚举 + 显式豁免，
不要手写集合。

**⑤ TDD 先导（AGENTS.md 测试铁律）**：
- **先写测试，跑，确认它是红的（预期内失败）**，再写生产代码。
- **每个被路由/worker/service 调用的核心函数，必须有一个不 mock 的冒烟测试**：
  真实构造最小输入直调该函数，走它内部真正的计算逻辑。
- mock 只允许用于：外部网络（LLM/embedding/rerank）、外部文件系统副作用。
  **绝不许 mock 掉被测函数的内部分支**。
- 探针/测试写完先问自己：**"如果我把被测逻辑改错，这个测试会红吗？"**
  答不上来就说明测试是空的。

**⑥ 变异门禁（新核心逻辑必做）**：
写一个 `.scratch/<feature>/mutation_check_*.py`，对**每一处新加的判断分支**，
在**子进程隔离**的环境里把它改错（删掉分支 / 反转条件 / 收窄判据），跑测试，
要求**必须变红**。要点：
- 每个变异体跑完必须**还原并复核还原是字节级干净的**（对比 sha256 或
  `git diff --stat` 为空）。探针 `finally` 里必须是「还原 + 复核」两步，
  一次崩溃也不许把变异体留在产品代码里。
- **变异体存活（MISSED）先做判据差集分析**：两处收窄判据重合时，砍掉一处
  确实可能无影响——去判断据的**差集**是什么场景，那才是变异体的活路。
  差集是真实可达的，就补测试；差集理论上不可达，才允许在票据里记录
  「判定为冗余」并附不可达的论证。
- **探针报红先怀疑探针**：手工跑却全绿 = 探针自己 bug。subprocess 传路径用
  列表不要用字符串；`rc=4` 通常是用法错误不是失败。
- 顺带做**反向变异**（把守卫整个删掉）确认测试会红，证明守卫不是装饰。

**⑦ 门禁全绿才准提交**：
```powershell
$env:PYTHONPATH="."
python -m pytest tests/ -q                      # 必须 0 failed
python scripts/run_forgetting_quality.py --check  # 必须 PASS
ruff check lantai tests scripts                 # 必须 0
ruff format --check lantai tests scripts        # 必须 0
```
`release_check.py` 的 lint 门禁是**最前一道**——它红的时候查版本/tag 没意义。
全绿后 `CHANGELOG.md` 的 `[Unreleased]` 收口（格式照上一条），再 commit。

**⑧ 收票**：`Status: done`，在票据末尾追加 `## Outcome`，写清：修法、测试名、
变异结论（KILLED 几个/共几个）、全量测试数、以及**这一票新学到的教训**。
最后一条最重要——它是下一个人（或下一次的你）唯一能收到的信息。

### 2. 不可逾越的红线

1. **不许 push、不许打 tag**。`git push origin master --tags` 是人类维护者的人工
   闸门。你只 commit 到本地，最后在报告里明确说「待推送 commit 如下」。
2. **不许跳过测试纪律**。没有不 mock 冒烟测试的核心函数改动，不许提交。
3. **不许静默丢弃数据**（宁 miss 不脏写）：校验失败/低置信度的东西进
   `pending_review` 待审队列，超龄自动归档 rejected，**绝不做"自动修正"**。
4. **不许改 `viewer_of` 这类单一收敛真源的语义**来绕过某个具体问题——
   在调用点改，别动承重墙。同类形状已在仓内多处成立时（如 `OR IS NULL`），
   新改动必须带上，不许只修半边。
5. **不许用 allowlist 式的护栏**。护栏必须枚举全量，并且用两个方向的变异实证
   它真的会红。
6. **探针/审计脚本不许留在产品目录**——全部放 `.scratch/<feature>/`，
   `extend-exclude` 已把 `.scratch` 排除在 lint 门禁外，别把它挪出来。
7. **遇到"该看的没看到"（观测面过窄）与"不该看的被看到"（越权泄漏）要分开定性**：
   前者是排障误导，后者是安全事故。修法方向相反，不许混为一谈。

### 3. 歧义裁决（不许问人，按这个定）

| 歧义 | 裁决 |
|---|---|
| 修法有两种，文档没定方向 | 选**与仓内既有设计一致**的那个。枚举仓内同形状实现，多数派即方向；然后在票据里记下少数派理由，供维护者事后翻案 |
| 新概念要起中文名 | 2–4 字、出自传统意象（官职/典籍/器物）、名实相副；**先在 `CONTEXT.md` 词汇表登记再用**；未登记不命名 |
| 改 API 契约/存储 schema/打分算法/安全策略 | 必须先写 `docs/adr/<NNNN>-<slug>.md` 再动代码 |
| 一个 bug 有两个独立成因 | 分两个 commit，一个 commit 只承载一个可独立变异验证的改动（01b 教训） |
| 修完发现相邻的第三个洞 | **另立一张票**，不塞进当前 commit；在报告里列出 |
| 测试跑不过且你判断是存量问题 | 不许改测试去迁就代码，也不许改代码去迁就测试——先判定谁错了，写进票据，再动手 |

### 4. 环境与运行纪律

- 虚拟环境：`.venv`（如使用受控环境另建，勿污染主环境）。
- 每次跑测试显式 `$env:PYTHONPATH="."`。
- 测试必须用**隔离的数据目录**：`db.engine` 在 import 时就会绑死宿主真实库路径，
  conftest 的隔离没生效时，你写的"测试"会真写到用户的记忆库去。开写测试前
  先确认隔离生效，别信文件 mtime 判断。
- 断言时刻用 aware datetime，**只锁时刻不锁时区**（sqlmodel 版本漂移会让
  `tzinfo` 随版本变）。
- 探针脚本输出若被终端吃掉，写文件再用 base64 读回来，别反复重猜。

### 5. 完成后必须交付的报告格式

```
## 本轮交付

### 已完成的票（逐张）
- <票据路径>
  - 先说影响：<一句话>
  - 修法：<一句话 + 文件:行号>
  - 测试：<测试文件名> <N> 例（含不 mock 冒烟 <M> 例）
  - 变异门禁：<K>/<K> KILLED（差集分析见票据）
  - commit: <short sha> <标题>

### 全量门禁
- pytest: <N> passed / 0 failed（基线 <B>）
- forgetting quality: PASS
- ruff check + format: 0

### 新建的票（修的过程中发现的）
- <路径> —— <一句话>

### 未动 / 需人工
- <票据> —— <原因>（ready-for-human 或需维护者决策）

### 待你确认的本地 commit（未推送）
git log --oneline origin/master..HEAD
```

### 6. 中断与恢复

如果会话中断，重进时按这个顺序恢复，不要从头猜：
1. `git status` + `git log --oneline -10` 看已有 commit。
2. 扫 `.scratch/*/issues/*.md` 的 `Status:`，找 `in-progress` 的那张——那是断点。
3. 读该票的 `## Comments` / `## Outcome`（若已有）确认进度到哪一步。
4. 从断掉的那一步继续，**已绿的门禁不要重跑**（耗时且结论会变——基线测试数在涨）。

## 使用说明（给维护者，不用粘给 Agent）

- **只复制「提示词正文」段**。本文档头部与尾部的说明是给你看的。
- Agent 跑完后，你只需要做一件事：审 `git log --oneline origin/master..HEAD`，
  满意就 `git push origin master --tags`，不满意就让它改。
- 想让 Agent 只做某一张票：把正文第 0 节的表格换成那一张，其余不动。
- 想让 Agent 只做调研不写代码：删掉第 1 节的 ⑤⑥⑦，让它只交「根因 + 影响面
  枚举 + 新建票据」三件套。
