# ADR-0039: 持节——智能体案牍巡检官与自主审批协议

**日期**: 2026-08-31  
**状态**: Accepted  
**决策者**: 大哥  
**来源**: 记忆管理自主化；解决传统方案依赖人工逐条点击、大模型缺乏标准接口主动治理与自治记忆库的痛点。

---

## 背景

1. **审阅疲劳**：日常高频交互下，`pending_review` 待审候选可能迅速累积，人工逐条决策耗时费力；
2. **智能体自治缺失**：接入 Lantai 的外部 AI（如 Hermes、Antigravity、Claude Code 等）此前仅能检索（`search`）或写入（`add`），缺乏标准协议参与记忆全生命周期的审查、降噪与确立；
3. **安全与降级纪律**：智能体代审必须遵循“宁 miss 不脏写”准则，对高确定性噪音自动归档、对高价值事实自动转为提案、对中段模糊事实执行披沙提纯，全流程审计记录。

---

## 决策

引入**「持节」（Chijie）** 智能体案牍巡检官机制，通过标准 MCP 协议开放三种颗粒度的自治与审批工具：

### 1. 核心工具集

1. **`triage_analyze`（智能研判）**：
   - 扫描待审候选库，调用结构化 LLM 研判链，返回包含 `approve` / `reject` / `refine` / `manual` 建议、置信度分与理由的结构化清单。
2. **`triage_apply`（批量审批）**：
   - 外部 Agent 确认研判建议后，批量提交决策，系统自动分流处理（`approve` 转提案、`reject` 归档、`refine` 提纯）。
3. **`triage_auto_pilot`（一键巡检自治）**：
   - 专为 Cron 定时任务、夜间沉淀或一句话 Agent 指令设计的全自动巡检流程。支持 `min_approve_conf`、`max_reject_conf` 阈值配置与 `dry_run` 预演模式。

---

## 理由

1. **典籍命名**：「持节」出自汉唐典制，天子特使持符节巡行天下、决断刑政，名实相称，象征赋予 AI 智能体自主裁决与巡检治理的特权。
2. **全流程闭环**：与「披沙」（ADR-0030）、「沉潜」（ADR-0036）深度联动，形成完整的自净化记忆生态。

---

## 影响

- 扩展 `lantai/services/auto_triage_service.py`（增加 `run_triage_auto_pilot`）。
- 扩展 `scripts/mcp_server.py`（注册 3 个新 MCP 工具）。
- 登记 `CONTEXT.md` 词汇表。
- 补充 `tests/test_mcp.py` 自动化测试。
