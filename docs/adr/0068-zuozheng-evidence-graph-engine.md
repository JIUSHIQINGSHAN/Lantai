# ADR-0068: 佐证（Zuozheng）——证据链反查与可解释性溯源图谱引擎

**日期**: 2026-10-30  
**状态**: Accepted  
**决策者**: 大哥  
**来源**: 针对检索结果缺乏可解释性支撑证据与决策溯源图谱的长跑演化需求。

---

## 背景

在 Agent 自主决策与长期记忆推理中，模型给出的断言需要具备强有力的**客观证据（Evidence）支撑**。
既有系统在证据侧存在如下断层：
1. `evidence.py` 仅为检索条目做简单的前缀截取，缺乏因果图谱（`MemoryEdge`）、原始来源（`RawDocument`）与同事实多维印证；
2. 缺乏专用证据反查引擎：Agent 无法针对特定记忆或断言，反向溯源完整的佐证拓扑；
3. 证据链条未经樊篱（`wrap_as_data`）围栏保护，极易被恶意构造的记忆源头渗透；
4. 认知上下文缺乏结构化证据切面，不利于人工审计与可信度自证。

---

## 决策

确立「佐证」（Zuozheng）证据链反查与可解释性溯源体系：

| 维度 | 决策 | 规范说明 |
|---|---|---|
| **命名出处** | 佐证（Zuozheng） | 出自《宋刑统》「案情显明，须得佐证」；喻指辅助证据、相互勘验印证与决策依据解释；见 [ADR-0013](0013-naming-system.md) 候选池转正，登记于 `CONTEXT.md`。 |
| **证据链拓扑数据契约** | `ProofChain` 与 `EvidenceNode` | 统一抽象记忆节点、因果推演边（causes / supports / refines）与原始文档来源，输出完整多跳证据链。 |
| **证据深度反查** | `ZuozhengEngine.inspect_evidence` | 沿图谱反向追踪直接支撑与因果前置记忆，计算综合置信度得分与溯源路径。 |
| **断言反向印证** | `ZuozhengEngine.verify_claim` | 输入自然语言主张，基于关键词与语义相似度动态召回支撑证据簇。 |
| **樊篱安全包裹** | 全链路 `wrap_as_data` | 所有证据节点正文强制以 `<memory_data id="...">` 包裹，附带证据源头与权重标记。 |
| **行级租户隔离** | `_check_access` 纪律 | 严格校验 `tenant_id` 与 `user_id`，跨租户越权证据彻底剪除，宁 miss 不脏写。 |
| **API 与 MCP 扩展** | REST + MCP 81 工具池 | 落地 `/zuozheng/inspect/{id}`、`/zuozheng/verify`，并注册 `zuozheng_evidence` MCP 工具，达成 81 工具里程碑。 |
| **认知上下文切面** | `CognitiveContext.zuozheng_digest` | 上下文生成时可挂载支撑证据链，输出清晰的 `[佐证·E1]` 结构化引用块。 |

---

## 影响

- 极大增强 Agent 决策的可解释性与可信度；
- 形成完整的「记忆检索 $\to$ 因果推演 $\to$ 佐证反查 $\to$ 上下文溯源」闭环；
- 系统 MCP 工具总数扩充至 81 个。
