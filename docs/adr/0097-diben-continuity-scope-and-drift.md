# ADR-0097: 底本跨会话传承与归属范围收敛

**日期**: 2026-11-25  
**状态**: Accepted  
**关联**: [ADR-0072](0072-diben-session-anchor-and-cognitive-continuity-engine.md)

## 背景

底本已有五段快照和意图漂移接口，但决策与待办未进入漂移对比；空查询会被当成显著话题偏离。列表字段以分号合并持久化，内容含分隔符时读取会拆坏。读取只比较属主且在未知当前租户时可能接受带租户行；同一 session_id 的写入删除也未限制归属。认知切面把 session_id 放进 Markdown 标题，缺少结构字段隔离。

## 决策

1. 不改存储表和外部响应字段。新列表值写入 `[DIBEN-LIST-V1]:` 标记和可逆反斜杠编码，保护 `;` 与 `\`；未带标记的历史值严格沿用旧分号拆分规则，包括分号前的反斜杠。长度门槛按未编码的逻辑文本计算。
2. 意图、下一步、工作区、决策和待办五段共同参与漂移判断。空查询或底本没有可比较词语时返回零分、不宣称延续或显著漂移，并给出“无法判断”理由；有匹配时按词语排序生成稳定理由。
3. 按统一 `SESSION_ID_PATTERN` 校验核心引擎、REST 和 MCP 输入。读查询按属主与租户收窄并 SQL 定靶；不带租户身份时只读取无租户行。写入替换只删除当前确切属主/租户下的同编号行，避免跨租户编号碰撞。
4. 查询定靶后只拼回相同 session_id、属主和租户的块，避免管理员全量查看时将不同归属共用编号的块混成一条底本。
5. 认知切面使用固定标题；会话编号包进 `wrap_as_data`，并压成单行。决策和待办容忍单字符串或列表输入。

## 后果

- 既有快照仍可读取，无数据库迁移；带版本标记的新值与未标记的旧分号文本采用各自确定的解析规则。
- 无租户身份的普通主体不再读取租户绑定行；普通写入不再覆盖其他属主或租户的同编号快照。
- 空白或无关键词输入不会被宣称为显著漂移；调用方可根据理由选择不附加历史上下文。
- 读取主查询有属主/租户 SQL 条件和 `LIMIT 1`，再以同一归属读取该会话的完整快照。
- 回归覆盖使用真实内存 SQLite；不改变发布版本或启用新表结构。
