# ADR-0091：会话原文先存的接收与恢复约定

Date: 2026-11-20
Status: Accepted for phase-one implementation

## 背景

用户选择先保存对话原文、之后再提取，并把 Obsidian 作为可选的人工阅读/整理入口。现有 RawDocument 由内容hash全局复用；普通提取发生在原文提交前；verbatim 会先调用embedding，现有异步线程池不持久保存待执行正文。它们不能直接承担按消息发生记录、重启恢复的接收语义。

## 决策

1. 新增独立的 ConversationMessage 与 ConversationJob，schema v47。旧 RawDocument、MemoryItem/verbatim 和既有入口不改写、不回填，不把内容哈希当消息身份。
2. MessageStore 是接收、读取、删除及租约的统一模块。调用方传入引擎与认证主体，每次操作拥有短事务。原文和待处理作业同一事务提交后才确认 durable。模块不依赖提取、embedding、Chroma或网络。
3. 逻辑消息身份为 user/tenant/agent + workspace/host/conversation/source_message 标签的组合。缺用户主体拒绝；tenant/agent 空表示无该维度但必须严格相等，绝不使用旧NULL共享读口径。来源标签只用于归因和去重，不证明真人、工作区授权或宿主最终准入。
4. 首期接受获准的 user 与 assistant 文本；同身份不同业务载荷报冲突，不支持隐式编辑、隐藏推理或系统消息。不同ID的同文字保留多次发生。文本保留原空白/Unicode，时间必须带偏移并归一UTC。
5. 持久化前检查正文和来源标签中的已知密钥形状，命中时返回固定错误。注入嫌疑正文可隔离保存，作业标记为 `held`，仅允许持有对应权限的用户显式查阅或下载。检测范围沿用现有规则。
6. 持久作业提供显式租约认领、读取、结算、有限重试；随机token与时钟解耦，迟到token、过期租约、已删除源均不能结算。首期不挂载自动worker、不调用模型、不创建候选/知识。作业completed仅表示内部消费者结算，不代表形成知识；后续提取接线必须另有来源关系与治理验收。
7. 删除清空正文与内容哈希，取消作业并清token、租约和错误原因，保留最小来源身份防旧消息重放。新同文消息仍可创建。首期不制造任何衍生正文、索引或业务日志副本；导出的用户文件与备份是额外副本，不声称自动擦除。
8. 显式 REST 需要有效服务密钥或库内 Bearer 凭据。其范围为凭据绑定的用户和空 tenant/agent，拒绝客户端自报的这两项请求头。`FEATURE_CONVERSATION_CAPTURE` 默认关闭，关闭时返回 404。接收接口固定错误文案并标记 `no-store`，跳过通用认知摘要响应头。底层模块可为后续绑定可信身份的适配器保留严格的三维范围。
9. Markdown为显式单向下载，原文置于足够长的代码围栏中。无Obsidian插件、目录监听、磁盘写入、自动导入或双向编辑。后续回流必须作为有稳定笔记身份/版本的新来源，而非覆盖原文。

## 取舍

增加两张表而不复用verbatim，避免把发生次数与内容去重混合，且保存不受模型可用性影响。同库持久作业比新增分布式队列更适合当前单进程部署。使用显式入口，先获得可验证接收基础，再按宿主真实生命周期接线；本期不是自动记忆或完整提取功能。

## 验证

公开MessageStore与REST seam均使用真实临时文件SQLite，覆盖同文不同发生/同身份冲突/进程重开/消息与作业原子性、严格user-tenant-agent范围、租约接管和旧token、删除后迟到结果和重放、禁网保存、默认关闭、校验错误脱敏、Markdown围栏。真实迁移回放核对新旧schema，无历史内容重写。模型、自动采集、跨备份净除、供应商撤回和Obsidian双向同步不在本期验收范围。
