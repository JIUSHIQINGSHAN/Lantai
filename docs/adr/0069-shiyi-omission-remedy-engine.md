# ADR-0069: 拾遗（Shiyi）——遗漏补偿与零召回自适应补救引擎

**日期**: 2026-10-30  
**状态**: Accepted  
**决策者**: 大哥  
**来源**: 针对在模糊查询、长尾表达或分词未对齐情境下出现的零召回与遗漏记忆长跑补救需求。

---

## 背景

在 Agent 对话交互中，记忆检索是模型获取上下文的核心路径。
然而生产环境暴露出以下典型痛点：
1. **零召回与语义失配**：当用户查询输入缩略词、口语化长尾表述或同义异构词时，BM25 词面无交集，纯向量召回可能因阈值过高被截断，导致空召回（Zero-Recall）；
2. **缺乏自适应降级补偿**：既有系统发生零召回后仅返回空数组，缺乏分步补救阶梯（同义词扩散、子串拆解、辨域放宽、时态跨越）；
3. **遗漏补偿不可审计**：补救召回与普通检索混杂，下游缺乏明确的「补救标记（remedy_tier / compensated_by）」；
4. **安全与隔离纪律**：自适应放宽时不得突破行级租户与属主安全隔离，正文仍须经樊篱（`wrap_as_data`）严密包裹。

---

## 决策

确立「拾遗」（Shiyi）遗漏补偿与零召回自适应补救引擎：

| 维度 | 决策 | 规范说明 |
|---|---|---|
| **命名出处** | 拾遗（Shiyi） | 出自唐代谏官官职「拾遗」（杜甫曾任左拾遗），取「捡回遗漏之物、补苴罅漏」之意；见 [ADR-0013](0013-naming-system.md) 候选池转正，登记于 `CONTEXT.md`。 |
| **多阶自适应补偿阶梯** | `ShiyiEngine.remedy_recall` | 阶梯 1: 宽松分词模糊子串重试；阶梯 2: 辨域/分轨范围安全拓宽；阶梯 3: 衰减惩罚动态回拨。 |
| **可观测补偿标记** | `RemedyCandidate` | 每条补救召回均明确携带 `is_remedied: True`、`remedy_tier` 与 `original_query`，对 Agent 决策完全透明。 |
| **樊篱安全包裹** | 全链路 `wrap_as_data` | 补救召回的正文强制施加 `<memory_data id="..." score="...">` 包裹，附带防注入说明。 |
| **行级租户隔离** | `_check_access` 纪律 | 任何补救阶梯坚决不得跨租户/越权泄露，严守「宁 miss 不脏写、宁漏不越权」。 |
| **API 与 MCP 扩展** | REST + MCP 82 工具池 | 落地 `/shiyi/remedy` 端点，并注册 `shiyi_remedy` MCP 工具，达成 82 工具里程碑。 |
| **认知上下文切面** | `CognitiveContext.shiyi_digest` | 当触发补救召回时，挂载 `## Compensated Recall & Remedied Memories (拾遗 · {count})` 切面。 |

---

## 影响

- 彻底根治生产环境模糊查询导致的空召回/错失核心约束痛点；
- 形成完整的「首轮混合初筛 $\to$ 零召回自动捕获 $\to$ 拾遗阶梯补救 $\to$ 上下文可解释注入」闭环；
- 系统 MCP 工具总数扩充至 82 个。
