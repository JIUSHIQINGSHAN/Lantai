# ADR-0055: API Key 哈希维持 SHA-256——PBKDF2 条件升级备忘

**日期**: 2026-10-25
**状态**: Accepted（现状不动 + 条件升级条款）
**决策者**: 维护者（授权自主开发；依据 `.scratch/v0.24-next-window-2026-10/issues/07-p1-7-tech-debt-i-j-d.md` 票 I 与 `docs/research/upstream-f03-gap-and-plan-2026-10.md` §PBKDF2 决策记录）
**来源**: 票据 `.scratch/v0.24-next-window-2026-10/issues/07-p1-7-tech-debt-i-j-d.md`（原十五天计划票 I，一票了结）

## 背景

上游 aiduMEI v22.0（2026-09-20 雷霆审计）把 API key 哈希升级为 PBKDF2 600k 轮。兰台现状：

- `lantai/core/auth.py:104`：`hashlib.sha256(raw_key.encode()).hexdigest()`——**无盐、单轮**。
- `lantai/core/auth.py:109`：key 本体由 `secrets.token_urlsafe(32)` 生成（`sk-` 前缀，256 bit 熵）。

## 决策

**现状不动**。理由：SHA-256 无盐对低熵口令是灾难（彩虹表+GPU 每秒百亿级），但对 256 bit 均匀随机串，暴力穷举空间 2^256——加盐与多轮拉伸不改变任何可计算的攻击成本（攻击者对单条 key 只能整体穷举，与哈希构造无关）。上游升级 PBKDF2 的场景是「可能允许弱 key」，兰台不存在该输入面。

**条件升级条款**（触发任一即重开本决策，升级为 PBKDF2 ≥600k 轮 + per-key 随机盐，并附迁移方案——存量 key 重新明文验证后换哈希或轮换）：

1. 任何路径允许**用户自设** key（弱熵输入面出现）；
2. key 熵源不再由 `secrets` 模块生成（如改为可读口令、截短、确定性派生）；
3. 哈希落库介质变更导致离线攻击面显著扩大（如哈希随备份同步到弱管控存储）。

## 影响

- 本 ADR 即票 I 的全部交付：一条备忘了结，不改代码、不加测试（现状无行为变更）。
- 上游差距分析（票 05 换基时）引用本 ADR 作为「已裁决、非缺口」项，不再列为待办。

## 后果

- 若未来触发条款而未升级，属违反本 ADR 的安全缺口——审计时以本文件为准绳。
