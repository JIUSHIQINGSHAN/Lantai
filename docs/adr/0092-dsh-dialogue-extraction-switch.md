# DSH 自动对话提取的独立开关

在 ADR-0091 的读取设置旁增加独立的自动提取设置。用户明确提取的含义为“自动从对话提取并写入兰台”。旧读取选择不能授权新的对话外发。

- 沿用同一 DSH profile、配置摘要和 Host 存储设施；读取保留原域，提取使用独立域与 extraction 记录，默认关闭。宿主禁止重复打开同名域，独立域避免句柄关闭和存储故障相互影响。旧 status/setEnabled 接口及其数据格式不变，新增 extractionStatus/setExtractionEnabled。新增接口继续核验实际 owner Peer。
- 在主对话上监听当前安装版的实时 `agent/inbox/spliced`，首次入队时只登记消息 ID 与当前提取许可代次；已有或恢复的 pending ID 不继承新许可，编辑、移位和重复插入同 ID 不刷新许可。开关或目录变化推进代次。之后仅允许同代 ID 对应的已提交 `user/message`，再筛选纯文本与直接用户来源；这里的提交指事件已被会话内存日志接受，不保证会话文件已物理落盘。子代理与未配置目录不接入，没有历史正文扫描或补传。
- 使用现有 /dialogue/async 接口，沿用用户归属、会话归属、请求归属和显式幂等键。完整提取、待审和演化留给兰台现有管线；客户端的 submitted 只代表取得任务排队回执，不宣称记忆已入库。
- 写入沿用当前 HTTPS / 严格 SSH 通道与凭据核验。单对话队列上限 16，输入长度 50000，凭据和提交共享当前配置的等待预算；错误仅返回固定原因码。关闭、换目录、卸载立即丢弃本地排队文本并取消在途请求。不自动重试，也不能撤销服务器已经接受的任务。
- 新设置不会打开读取设置；关闭读取也不隐式改变提取设置。变更连接或资料范围会使各自保存的选择失效。
- 提取前按服务端已验证身份核对归属；API Key 模式对应 `api_key`，沿用已有的管理员元数据接口。Bearer 使用新增 `GET /dialogue/identity`，只返回真实 principal 的 `user_id` 与生效 `tenant_id`，不读取记忆；拒绝无凭据开发模式、混合认证头与非用户角色。旧服务端缺接口时以 `identity_unavailable` 停止正文；身份不匹配以 `ownership_mismatch` 停止正文。预检查使用同连接、同凭据、同租户，不携带对话正文；预检查与提交不是同一数据库事务，依赖凭据归属稳定与网关配置一致。没有改变已有鉴权优先级或对话写入契约，也不自动部署服务端。设置和状态只展示元数据及固定原因码。
- 设置中的停止及故障提示只承诺停止本地自动提交，不能撤销兰台已接受的任务；已接受任务仍可能继续处理并写入。两项重试入口的可访问名称包含各自设置名称，开关与重试均关联保存反馈。

验证入口：插件 extraction.test.mjs、真实 DSH runtime.test.cjs、真实存储 preference-runtime.test.cjs 和两设置 Client 行为测试。
