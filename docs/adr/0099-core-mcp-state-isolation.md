# ADR-0099：核心报告快照与 MCP 并发边界

状态：接受

## 背景

Stage 5-C 的真实回归证明，考功和巩固周期结果、报告读取结果与进程缓存共享同一
嵌套对象。调用方修改 `details`、`score_factors`、`warnings` 或状态字段会污染
后续读者。MCP 守卫冷启动也可能为并发调用创建多个实例，分散失败计数。

测试工装原来浅复制报告，内层列表可同时修改运行值和复位基线。默认工具档位
测试只登记会话级环境恢复，不能保证逐例精确恢复。

## 决策

1. 考功与巩固报告发布时深复制后再替换缓存引用，读取时深复制，保留现有字段、
   值与访问范围。周期调用者和报告读者都获得独立快照，不改变报告持久化规则。
   跨身份直调仍返回相同内容，管理员路由守卫继续承担授权；原安全回归改验内容
   完整一致，并新增副本及嵌套对象独立、调用方修改不污染其他读者或缓存的断言。
2. MCP 守卫首次创建由进程内锁保护；已有守卫继续复用。此锁不串行化 handler，
   不提供跨进程互斥，也不改变 LoopGuard 的失败窗口、阈值与单探针规则。
3. 非字符串 MCP 方法字段返回 JSON-RPC 无效请求 `-32600`，后续帧继续处理。
   未知的字符串方法仍为 `-32601`；工具档位与资源协商契约保持原有语义。
4. 工装递归复制容器，保留懒单例引用。需要运行核心服务的测试显式认领守卫与
   报告状态；未认领的污染仍由原有护栏记录并回滚，不增加豁免名单。
5. 测试的档位环境采用按例上下文；子进程显式指定临时 SQLite/Chroma 路径。

## 影响与验证

报告的 JSON 内容与外部 API 形状兼容，禁止依赖返回对象身份来写缓存。深复制
成本随报告大小增长；不新增缓存或后台任务。回归包含真实 SQLite 四写四读、
八线程守卫冷启动、并发半开单探针、真实 stdio 与环回 HTTP。证据与验收结果
见本检出 `.scratch/stage5-core/`。
