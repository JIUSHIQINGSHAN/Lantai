# ADR-0013: 中文命名体系——意象取材与命名规则

**日期**: 2026-08-11
**状态**: Accepted
**决策者**: 大哥
**来源**: 项目命名复盘（兰台定名后，为后续功能提供统一命名方向）

## 背景

兰台记忆从 aiduMEM 移植以来，术语长期中英混杂：机制层保留英文技术名（gate / coalesce / decay / checkpoint / lane / tier），中文意象名零散出现（潮波、闸门、护盾、锦囊），新功能持续快速落地（scene / digest / verbatim / skill / conflict / autodream / 反思 / 观察期）。若不建立统一体系，演进中会出现三类问题：

1. **重名与撞车**——意象池没有登记，新功能可能重复占用或语义漂移；
2. **风格漂移**——有的名取典故、有的直译、有的音译，观感割裂；
3. **追溯成本**——每次改名都要走数据/部署迁移，越晚越贵。

## 决策

确立系统化中文命名体系：**每个正式名称都必须「有出处、有意义、有登记」**，按对象层级从传统意象取材，遵循固定规则登记使用。

### 1. 命名层级（按对象选意象域）

| 层级 | 对象示例 | 取材倾向 | 例 |
|------|---------|---------|----|
| L0 项目 | 项目名、仓库、产品 | 官署/机构 | 兰台（汉代皇家档案馆） |
| L1 子系统 | 模块、服务、通道 | 官职/机构/器械 | 闸门（准入）、拾遗（检索）、更漏（时间） |
| L2 机制 | 算法、策略、队列、流程 | 典籍/典故/成语 | 潮波（合并）、锦囊（待审）、参商（矛盾） |
| L3 数据实体 | 表、文件、集合、文档 | 器物/书册/簿籍 | 青简（记录）、卷宗（场景）、目次（概览） |
| L4 版本代号 | 每个发行版本 | 典籍词，按序列推进 | v0.6 青简 → v1.0 兰台 |

### 2. 意象三大来源

- **官职/机构**：兰台、石室（金匮石室）、拾遗（唐谏官）、考功（吏部考功司）、起居注（帝王言行档册）
- **典籍/典故/成语**：锦囊妙计（三国演义）、吾日三省（论语·学而）、参商（左传）、校雠（刘向别录）、秉笔直书（左传·董狐）、拟之而后言（易·系辞）
- **器物/自然意象**：青简（竹简）、缥缃（丝帛书衣）、更漏（铜壶滴漏）、潮波、尘封、青鸟（西王母信使）

### 4. 硬规则

- **R1 形制**：正式中文名 2–4 字；单字名仅限项目级；不做四字以上短语名。
- **R2 出处**：每个名字必须写明出处与含义（登记时一并写入词汇表）；无出处的名字不采用。
- **R3 语义**：意译优先、名实相副——名字须指向功能本质，不做纯装饰。
- **R4 登记**：任何新正式名称必须先登记 `CONTEXT.md` 词汇表（附 ADR/出处引用），未登记不得投入使用。
- **R5 唯一**：与既有名称（含谐音）冲突时，改选同域其他意象；禁止一物多名、同名异义。
- **R6 代号对应**：英文技术标识（类名/表名/枚举/环境变量）与中文名在词汇表一一对应；新代号用拼音转写（首字母大写，如 Lantai / Jinnang），沿用既有英文技术名时保留（gate / lane）。
- **R7 版本代号**：每版取一个典籍意象词，按固定序列推进并在 CHANGELOG 登记；代号须贴合该版主题。
- **R8 落地标识**：文件名、数据库/集合名、插件名等落地标识的改名必须走「安全迁移 + 兼容回退」流程（参考 migrate_home / ADR-0001 门面铁律），禁止直接改——宁 miss 不脏写。

### 5. 反例（负面清单）

- ❌ 新引入希腊/罗马神话名（既有 Chronos 保留、不追溯）
- ❌ 生僻字、异体字、繁简混用
- ❌ 流行网络梗、纯外来音译（gate 不叫「盖特」）
- ❌ 无含义的音译、无意象的英文直译
- ❌ 同一对象叠加多个意象，或意象与功能无关

### 6. 实施

- 本 ADR 生效后，新功能票据/新概念命名必须先过规则自检 + 词汇表登记；命名不合格的票据退回补充。
- 既有中英混杂术语不强制追溯改名；在对应功能重构/迁移窗口期按本体系收敛（改名必须同时满足 R8）。
- 意象池开放扩充：新增意象需注明出处，避免重复占用。

## 影响

- 新功能开发增加一道「命名登记」工序（低成本、防漂移）。
- 未来改名集中在数据/部署标识，迁移成本受 R8 约束可控。
- `CONTEXT.md` 词汇表成为命名事实来源（source of truth）。
