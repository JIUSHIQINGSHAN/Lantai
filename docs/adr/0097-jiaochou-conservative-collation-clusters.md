# ADR-0097: 校雠双向保守订误与完全链接冗余簇

**日期**: 2026-11-25  
**状态**: Proposed  
**来源**: ADR-0070 校雠引擎在真实输入与存量扫描中的语义强化。

## 背景

校雠首版以词集 Jaccard 决定 `merge` / `update`，却只返回 B 相对 A 的差异。高词面重合的端口、地点或日期替换可能被合并；相反，单凭输入次序选择一侧也不能证明它是现行值。冗余扫描虽然算出相似配对，尚未显式提供簇成员及簇内关系，单链传递还可能把彼此不相似的记忆串到一起。

## 提议

| 项 | 决策 |
|---|---|
| 双向分歧 | `divergence_tokens_a` 与 `divergence_tokens_b` 分列两侧；旧 `divergence_tokens` 继续等于 B 相对 A，保持既有调用兼容。词项稳定排序。 |
| 订误动作 | 对 A→B 与 B→A 分别调用既有 `classify_relation`。两向均为 `merge` 才建议 `merge`；恰为一向 `update`、反向 `merge` 时，建议该方向的更新稿；其余（含双向值冲突、关系不一致）均 `retain_both`，并保留两源文本等待核验。引擎只出建议、不落库。 |
| 簇定义 | 在不超过 100 条候选池的完整阈值候选图上，按相似度与 ID 稳定排序贪心合并完全链接组；只有成员两两存在候选边才同簇。未报告的输出边仍参与识别，缺失交叉候选边则不桥接。 |
| 簇报告 | 配对详情仍严格受 `limit` 限制；另报簇总边数、已报告/省略边数、相似度下界和共同/分歧词项。每簇给一个代表配对建议；有任何未逐对校勘边时，簇汇总动作强制 `retain_both` 并明确待核，不能据此整簇合并。 |
| 置信度 | 混合 Jaccard 与动作档位的启发式排序分，不宣称校准概率，并在元数据显式标记未校准。 |
| 资源与隔离 | 沿用票 59 的 100 行候选池上界、既有行级 ACL 与输出对数上限；完整候选图最多 4,950 条边，簇识别不增加数据库扫描或写入副作用。仅对一个没有任何详情边的簇额外校勘一个代表配对，不增加 LLM 调用。 |

## 影响

- 双源比较可以完整呈现双方差异；冲突值不再因高相似度被建议合并，也不按 A/B 顺序猜现行值。
- 扫描调用方可拿到不受配对详情截断影响的冗余簇；逐边详情保持限额，省略边明确计数，代表建议不冒充逐边核验，完全链接避免单链误聚。
- API/MCP 响应仅增加字段；原字段与入口不变。
- 词项 Jaccard 与现有结构规则仍是有限启发式，不等价于经人工标注集校准的事实判定。
