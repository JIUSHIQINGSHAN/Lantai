# DSH 发布门禁正向控制的 Node 前置条件

## 现象与复现

v0.70.0 整合后的完整发布门禁运行 5164 项测试，结果为 5155 项通过、7 项跳过、
2 项失败。失败均来自 `tests/test_skip_mask_inventory.py`：新增的 Node 缺失跳过
没有登记，且其 `_NODE is None` 守卫不属于扫描器直接识别的环境能力表达式。
该轮验收前后源码指纹一致，没有以中途进度或单项重跑充当全仓通过。

最小复现入口为 `tests/test_dsh_core_release_gate.py` 与
`tests/test_skip_mask_inventory.py`。证据保存在本次发布的工程票据及
`.scratch/release-20261126/evidence/`，不涉及生产记忆或真实宿主配置。

## 根因

适配器修复将正向控制从接受任意 `--version` 命令收紧为真实 Node 语义版本，
但在找不到 Node 时新增了 `pytest.skip`。这会让正向控制在前置能力缺失时弃权，
使真实 Node 成功路径未被执行。发布门禁本身要求 Node 可用，不能用跳过代替验证。

增加一个真实 pytest 子进程反证：清空子进程 PATH，移除显式 Node 选择，
只执行原正向控制。修改前子进程输出 `1 skipped` 并以退出码 0 结束，
反证因此失败；与两项原审计一起，定向红相为 3 项失败、8 项通过。

## 最小修复与边界

将缺少 Node 的跳过分支改为显式断言失败。真实 Node 正向路径、缺失命令、
非法路径及 Python 冒充 Node 的门禁断言均保留。反证继续通过实际 pytest
子进程观察失败退出码、失败计数和明确原因，不模拟门禁内部计算。

跳过扫描器与其 17 处申报清单保持不变，没有新增豁免、删减断言或放宽超时。
这是测试前置条件修复，产品运行代码、依赖和对外协议均不变。

## 定向验证与完整放行条件

冻结开发环境下，两份受影响测试正向为 11 项通过（39.42 秒），按 JUnit 条目
严格倒序后仍为 11 项通过（35.06 秒），均带覆盖率且退出码为 0。全量 Ruff
检查通过，878 个文件格式正确。反证观察真实 pytest 进程的返回值与输出，
没有替换门禁内部逻辑；审计扫描器和申报清单的 Git 差异为零。

上述结果仅覆盖定向修复验证。提交后仍须在同一干净提交上重新运行完整发布门禁、
覆盖率与宿主库绊线，以及同清单严格反向全仓。最终放行只认两轮完整证据，
不得把定向通过代替全仓通过。
