## 复现与根因

1. 解析器原先在整段文本中搜索肯否词，疑问、假设、双重否定和离题片段会触发裁决。首批7条定向用例均失败；边界补测进一步复现“正确的做法是先查证”“保持好心情”“没有时间讨论”三种误判。
2. 认知层已有第三值修订，但公开服务冲突分支仍用另一套肯否分类，修订不能经既有 REST/MCP 入口写入。复用同一解析函数，保留模糊记忆、原子事实原有语义。
3. 认知层否定分支直接写冲突状态，无法阻止并发覆盖终态；FTS 同步失败被捕获后继续提交，可能出现正文、快照、索引不一致。两个入口改为复用支持调用方会话的冲突裁决 CAS，并在异常时回滚。
4. 首次探颐修改只产生一条含 `before/after` 的快照，既有回滚要求至少两条，导致首次改写不可恢复。只为符合相邻版本条件的探颐首条快照使用 `before`；多快照规则不变。
5. 含糊回复原来没有观测计数。使用冲突 `detail` 中的累计计数，SQL 表达式原子递增；不保存原话、不更改正文或版本、不重新打开终态。
6. 新分句解析在自审中暴露出第三值标点被截断的回归，4条红测确认网址只剩 `https`、逗号后事实丢失、引号包裹修订未识别。修订词仍按小句定位，但事实值改从原文剩余片段完整提取，避免把标点当作事实结束。
