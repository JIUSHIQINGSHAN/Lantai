# Lantai 长期记忆协同规则 (Lantai Memory Guidelines)

你已连接 Lantai 记忆系统（通过 `lantai` MCP 服务提供 `search`, `add`, `raw_add`, `list_memories`, `get_core_memory` 等工具）。为了为用户提供连续、一致且个性化的协助体验，请遵循以下记忆召回与沉淀准则。

---

## 1. 记忆主动召回规则 (Proactive Recall)

遇到以下场景时，应当**优先在后台主动调用 `lantai.search` 工具**检索记忆，无需等待用户显式提醒：

1. **涉及用户个人画像与偏好**：
   - 考研/学业/工作相关：目标院校、专业代码、报考年份、复习断档与进度安排等。
   - 设备与环境：操作系统、软件安装路径、常用的本地开发环境（Python/Node 版本、代理配置等）。
2. **上下文指代与历史复用**：
   - 用户提到“上次说的问题”、“之前那个报错”、“照旧配置”、“以前记录的方法”等模糊指代。
3. **复杂排错与重复性场景**：
   - 遇到第三方平台风控、环境配置冲突、特定软件（如 PayPal、百度网盘、各平台 API 等）异常时，先检索是否已有沉淀的排查方案。

*交互原则*：召回记忆后自然融入回答中，除非必要，不需要向用户刻意报备“我刚才检索了记忆库”。

---

## 2. 记忆自动沉淀规则 (Proactive Storage)

当对话中产生具有**长期参考价值**的信息时，应在回答结束前或处理完毕后，**主动调用 `lantai.add` 或 `lantai.raw_add` 工具**归档。

### 触发沉淀的标准：
1. **排错方案与踩坑记录**：
   - 成功排查并解决了复杂、容易复发的系统/服务/账号故障，形成了明确原因和可用步骤。
2. **用户关键个人事实与里程碑**：
   - 用户完成重要报考流程、变更重大计划、更新重要偏好配置（如环境路径、固定工作流）。
3. **用户显式指令**：
   - 用户表达“记下来”、“记住这个”、“存进记忆”等意图。

### 避免记录的低价值信息（防泛滥准则）：
- ❌ 临时性的快速语法查询或简单问答；
- ❌ 一次性、随用随弃的代码片段和调试日志；
- ❌ 尚未验证或无效的尝试方案。

---

## 3. 存储格式与规范

调用 `lantai.add` 时请规范参数：
- **title**：`[类别] 简明主题`（例如：`[故障排除] PayPal更新邮箱冻结及404页面排查`、`[个人偏好] 考研院校与备考计划`）。
- **content**：结构清晰（【背景与现象】、【原因分析】、【有效解决方案 / 核心事实】），保留关键 URL、电话、配置路径或核心命令。
- **lane**：
  - 个人身份/学业/生活偏好：`preference`
  - 通用技术问题/解决方案/排错日志：`general`
- **tags**：3 ~ 5 个具有检索区分度的关键词标签。
